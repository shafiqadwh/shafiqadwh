# Photo Booth

บูธถ่ายรูปที่ **พิมพ์ออกมาให้แขกทันที** พร้อม QR ให้สแกนโหลดไฟล์ดิจิตอล
ขายแยกได้ หรือขายคู่กับเว็บแชร์รูปในโปรเจกต์เดียวกันนี้

## สถานะตอนนี้

**แกนประกอบแผ่นพิมพ์เสร็จแล้วและทดสอบครบ** — ส่วนกล้องกับเครื่องพิมพ์ยังไม่ได้ทำ

| ส่วน | สถานะ |
|---|---|
| ผังแผ่นพิมพ์ 4 แบบ (เต็มใบ · แถบยาว · สี่ช่อง · โพลารอยด์) | ✅ |
| เอฟเฟคแต่งภาพ 7 แบบ | ✅ |
| ธีมตามงาน 8 แบบ (รวมฮารีรายอ อีดิลฟิตรี/อีดิลอัฎฮา) | ✅ ใช้ไฟล์เดียวกับเว็บแชร์รูป |
| ชื่องาน + QR บนแผ่น รองรับไทย/มลายู/อังกฤษ/อาหรับ (RTL) | ✅ |
| หน้าจอบูธ (กล้อง นับถอยหลัง เลือกเอฟเฟค ดูแผ่น) | ✅ |
| **สองจอสัมผัส** — จอหน้าให้แขก จอหลังให้ช่างภาพ สั่งงานได้ทั้งสองจอ | ✅ |
| **รีโมทกดถ่าย** ทั้งแบบเสียบสายและบลูทูธ | ✅ ไม่ต้องลงไดรเวอร์ |
| **โหมดไม่ต้องพิมพ์** — ขึ้น QR บนจอ แขกสแกนรับไฟล์ทันที | ✅ ขายได้โดยไม่ต้องมีเครื่องพิมพ์ |
| ส่งรูปขึ้นเว็บ + หน้า `/p/<รหัส>` ที่ QR ชี้ไปหา | ✅ |
| เก็บรอบถ่ายลงดิสก์ + โทเคนสำหรับ QR | ✅ |
| สั่งพิมพ์ | ⚠️ โหมดแฟ้มใช้ได้ · โหมด CUPS **ยังไม่เคยทดสอบกับเครื่องพิมพ์จริง** |
| พิมพ์บนอิงค์เจ็ท A4 (วางแผ่นกลางหน้า + เส้นตัด) | ✅ ดู [`docs/demo-setup.md`](docs/demo-setup.md) |
| หน้าตั้งค่าในแอป | ⬜ ยังแก้ผ่าน `settings.json` |
| อัปโหลดขึ้นเว็บให้ QR ชี้ไปหา | ⬜ ยังไม่ได้ทำ |

## โครงสร้าง

```
photobooth/
  src/core/     ← ไม่รู้จักกล้อง เครื่องพิมพ์ หรือ Electron เลย
    paper.js       ขนาดสินค้า (4×6) กับขนาดหน้ากระดาษ (A4) — คนละเรื่องกัน
    mount.js       วางแผ่นขนาดสินค้าลงหน้ากระดาษจริง พร้อมเส้นตัด
    templates.js   ผังของแต่ละแบบ คิดจากสัดส่วนกระดาษ
    effects.js     เอฟเฟคแต่งภาพ (ปรับค่าสีล้วน ไม่มีไฟล์ภาพของใคร)
    sheet.js       ประกอบแผ่น: รูป + ชื่องาน + QR
    keys.js        ปุ่มรีโมท → การกระทำ (ตารางเดียว ใช้ทั้งหน้าจอและฝั่งหลัก)
  src/main/     ← Electron main process — งานหนักทั้งหมดอยู่ฝั่งนี้
    main.js        หน้าต่าง + IPC + สะพานระหว่างสองจอ
    windows.js     แจกจอให้สองหน้าต่าง · มีจอเดียวได้หน้าต่างเดียว
    remote.js      ปุ่มที่ต้องยึดระดับระบบ (ปุ่มเสียงที่เดสก์ท็อปกินไปก่อน)
    settings.js    ค่าตั้ง · ค่าที่ผิดตกกลับไปค่าที่ใช้ได้ ไม่ใช่ทำให้บูธไม่ขึ้น
    session.js     หนึ่งรอบถ่าย = หนึ่งโฟลเดอร์ + โทเคน
    print.js       ตัวขับเครื่องพิมพ์ (file / cups)
    preload.cjs    สะพานเดียวไปหาหน้าจอ
  src/renderer/ ← สองหน้าจอ (จอสัมผัส ไม่มีคีย์บอร์ด)
    index.html     จอหน้า — แขกเป็นคนดู เป็นเจ้าของกล้องและเจ้าของสถานะ
    operator.html  จอหลัง — ช่างภาพเป็นคนดู สั่งงานได้ แต่ไม่จำสถานะเอง
  test/
```

`src/core/` รับ buffer เข้า คืน buffer ออก **ทดสอบได้ครบโดยไม่ต้องมีฮาร์ดแวร์**
ซึ่งจำเป็น เพราะเป็นชิ้นที่ผิดแล้วรู้ตอนกระดาษออกจากเครื่องพิมพ์ไปแล้ว

## ของที่ใช้ร่วมกับเว็บแชร์รูป

อยู่ที่ `../shared/` — **แหล่งเดียว ห้ามก๊อปไปไว้สองที่**

- `themes.json` / `themes.js` — สีและเอฟเฟคที่แนะนำต่อประเภทงาน
  ลูกค้าคนเดียวกันซื้อทั้งสองอย่างเป็นแพ็กคู่ ถ้าสีบนเว็บกับบนรูปที่พิมพ์ไม่เหมือนกัน
  แขกเห็นทันทีตั้งแต่แผ่นแรกที่ถือขึ้นมาเทียบกับจอ
- `text.js` — เรนเดอร์ตัวหนังสือด้วย Pango (ไทย/อาหรับถูกต้อง ฟอนต์เดินทางมากับโปรเจกต์)

## รัน

```sh
npm test                          # จากรากโปรเจกต์ รันทั้งเว็บแชร์รูปและ photo booth
node --test photobooth/test/*.test.js

cd photobooth && npm start        # เปิดบูธจริง (เต็มจอ · ใช้จอที่สองเองถ้ามี)
BOOTH_WINDOWED=1 npm start        # เปิดแบบหน้าต่าง ตอนตั้งค่า
BOOTH_OPERATOR=1 npm start        # บังคับเปิดจอช่างภาพ แม้เครื่องมีจอเดียว (ซ้อม)
```

`test/app.test.js` ขับแอปจริงทั้งตัวผ่าน Electron + กล้องจำลองของ Chromium
ยก Xvfb ขึ้นเองถ้าเครื่องไม่มีจอ — จึงรันได้ด้วย `npm test` เฉย ๆ ไม่ต้องเตรียมอะไร

## ค่าตั้ง

อยู่ที่ `<userData>/booth/settings.json` (macOS/Linux/Windows ตามที่ Electron กำหนด)
ตั้ง `BOOTH_USER_DATA` ชี้ไปที่อื่นได้ตอนซ้อม เพื่อไม่ให้ทับของงานจริง

| ค่า | ความหมาย |
|---|---|
| `eventTitle` / `eventSubtitle` | ชื่องานกับบรรทัดรอง บนแถบล่างของแผ่น · **เว้นว่างทั้งคู่และปิด QR = ไม่มีแถบล่าง รูปกินเต็มแผ่นแทน** |
| `theme` | ธีมสีจาก `shared/themes.json` |
| `template` | `classic` · `strip` · `grid` · `polaroid` |
| `effects` | เอฟเฟคที่จะให้แขกเลือกหน้างาน (มากสุด 4) |
| `countdownSeconds` | 2–10 |
| `copies` | 1–4 ใบต่อการกดพิมพ์หนึ่งครั้ง |
| `qrMode` / `baseUrl` | `off` / `later` / `live` · ไม่มี `baseUrl` = ไม่มี QR ไม่ว่าตั้ง mode ไว้อย่างไร |
| `printer.driver` | `file` (ค่าเริ่มต้น เขียนลงโฟลเดอร์ขาออก) หรือ `cups` |
| `deliver` | แขกได้รูปทางไหน: `print` · `screen` (QR บนจอ) · `both` |
| `uploadKey` | กุญแจเดียวกับ `BOOTH_KEY` ฝั่งเว็บ · ASCII อย่างน้อย 16 ตัว |
| `printPage` | `same` = กระดาษเท่าขนาดสินค้า (dye-sub) · `A4`/`A5`/`letter` = วางกลางหน้าแล้วตัดเอง |
| `operatorScreen` | `auto` (ใช้จอที่สองถ้าเสียบไว้) หรือ `off` |
| `remote.enabled` | รับปุ่มจากรีโมทหรือไม่ (ค่าเริ่มต้นรับ) |
| `remote.globalKeys` | ปุ่มที่ยอมให้ยึดทั้งเครื่อง — ว่างไว้เป็นค่าเริ่มต้น ดูหัวข้อรีโมท |

## สองจอ + รีโมทกดถ่าย

เสียบจอสัมผัสตัวที่สองแล้วเปิดบูธ — **ไม่ต้องตั้งอะไรเพิ่ม** จอหลัก (ที่ระบบตั้งเป็น
primary) กลายเป็นจอหน้าให้แขก จออีกตัวขึ้นหน้าช่างภาพให้เอง · มีจอเดียวก็ได้
หน้าต่างเดียวเหมือนเดิม ไม่ใช่สองหน้าต่างซ้อนกัน

จอหลังเห็นภาพสดจากกล้อง (จอหน้าส่งต่อมาให้ 4 ภาพ/วินาที — **กล้องตัวหนึ่งเปิดได้
ทีละที่เดียว** จอหลังจึงเปิดเองไม่ได้), เห็นแผ่นที่ประกอบเสร็จ, รหัสของรอบนั้น,
จำนวนแผ่นที่พิมพ์ไปแล้ว และมีปุ่มสั่งงานสองปุ่ม

**สถานะมีเจ้าของที่เดียวคือจอหน้า** จอหลังส่งคำสั่งไปแล้วรอดูผลกลับมา — สองจอที่
ต่างคนต่างจำว่าตอนนี้ถึงไหนแล้ว คือสองจอที่พูดไม่ตรงกันทันทีที่มีอะไรพลาด

### รีโมท

รีโมทกดชัตเตอร์ทั้งแบบเสียบสาย USB และแบบบลูทูธ (AB Shutter และรุ่นคล้ายกัน)
**ประกาศตัวกับระบบว่าเป็นคีย์บอร์ด** เสียบแล้วใช้ได้เลย ไม่ต้องลงไดรเวอร์
กดปุ่มเดียวได้ทั้งกระบวนการ เพราะปุ่มนั้นหมายถึง "ทำขั้นต่อไป" ไม่ใช่ "เริ่มถ่าย"

| ปุ่มที่รับ | ความหมาย |
|---|---|
| `Enter` `Space` `PageDown` `F5` `Num0` `VolumeUp` | ขั้นต่อไป: เริ่มถ่าย → พิมพ์ → ถ่ายรอบใหม่ |
| `PageUp` `VolumeDown` `Backspace` | ถอย: ทิ้งแผ่นนี้แล้วถ่ายใหม่ |

- กดรัวหรือรีโมทเด้งสัญญาณ ปุ่มเดิมภายใน 0.35 วินาทีถูกเมิน — **สั่งพิมพ์ซ้ำย้อนไม่ได้**
- ระหว่างนับถอยหลังและระหว่างกำลังพิมพ์ รีโมทไม่รับคำสั่ง เหมือนปุ่มบนจอที่ตายอยู่แล้ว
- ปุ่มเสียงบน Linux เดสก์ท็อปยึดไว้ก่อน หน้าต่างไม่มีวันเห็น — ถ้ารีโมทส่งปุ่มนั้น
  ให้ใส่ `"remote": { "globalKeys": ["VolumeUp", "VolumeDown"] }` เพื่อยึดระดับระบบ
  **ค่าเริ่มต้นไม่ยึดอะไรเลย** เพราะยึดไว้แปลว่าโปรแกรมอื่นบนเครื่องนั้นใช้ปุ่มนั้น
  ไม่ได้จนกว่าจะปิดบูธ

## โหมดไม่ต้องพิมพ์ — ขายได้ก่อนซื้อเครื่องพิมพ์

ตั้ง `deliver: "screen"` พร้อม `baseUrl` และ `uploadKey` แล้วหลังถ่ายเสร็จ
บูธจะส่งรูปขึ้นเว็บทันทีและ **ขึ้น QR ใหญ่บนจอ** ให้แขกสแกนรับไฟล์ตรงนั้นเลย
ไม่ต้องมีเครื่องพิมพ์ ไม่ต้องมีกระดาษ ไม่ต้องมีหมึก

- ตั้ง `screen` ไว้แต่ยังไม่มี `baseUrl`/`uploadKey` จะถูก**บีบกลับเป็น `print` ให้เอง**
  — จอที่ขึ้น QR ที่สแกนแล้วไม่มีอะไร แย่กว่าไม่มีโหมดนั้นเลย
- เน็ตล่มตอนนั้น QR ยัง**ถูกต้อง**และยังขึ้นให้ พร้อมข้อความว่ารูปจะมาทีหลัง
  · ลิงก์ใช้ได้ตั้งแต่แรกเพราะรหัสถูกจองไว้ตั้งแต่ตอนถ่าย
- `deliver: "both"` = พิมพ์ด้วย ขึ้น QR ด้วย

## เดโมด้วยอิงค์เจ็ท

ยังไม่มี dye-sub ก็เดโมได้ — ตั้ง `printPage: "A4"` แล้วแผ่นขนาดสินค้าจะไปนั่งกลาง
หน้า A4 พร้อมเส้นตัดที่มุม **ขนาดที่ออกมาเท่าสินค้าจริง ไม่ถูกย่อ** และ A4 หนึ่งแผ่น
ใส่ได้สองใบ (แบบ `strip` = 4 แถบต่อกระดาษหนึ่งแผ่น) · ขั้นตอนตั้งเครื่องทั้งหมด
รวมถึง OS ที่แนะนำและวิธีหาชื่อเครื่องพิมพ์ อยู่ใน [`docs/demo-setup.md`](docs/demo-setup.md)

## ข้อควรรู้ที่จ่ายค่าบทเรียนไปแล้ว

1. **ไฟล์กรอบบูธถ่ายรูปที่แจกบน Instagram/X ห้ามใช้เชิงพาณิชย์** งานนี้ตั้งใจขาย
   เอฟเฟคทุกตัวจึงสร้างเองจากการปรับค่าสีล้วน ไม่มีไฟล์ภาพของใครในโปรเจกต์
2. **`.tint()` ของ sharp เป็น duotone** มันกลืนสีเดิมทิ้งทั้งหมด ไม่ใช่ "ทำให้อุ่นขึ้น"
   (พิกเซลฟ้า 120,150,200 → น้ำตาล 175,143,99) ใช้ `linear()` ต่อช่องสีแทน
3. **`stats()` ของ sharp อ่านจากภาพต้นทาง ไม่สนใจ `extract` ที่ต่อในไปป์ไลน์**
   ต้องตัดออกมาเป็นภาพใหม่ก่อนแล้วค่อยวัด
4. **ขนาด QR ที่สแกนติดวัดที่ "ขนาดโมดูล" ไม่ใช่ขนาดรวม** ที่อยู่ยาวขึ้น = โมดูลถี่ขึ้น
   ในกรอบเท่าเดิม · ตัวตัดสินจริงยังคงเป็นการเอากระดาษที่พิมพ์แล้วมาสแกนด้วยมือถือ
5. **`width` กับ `dpi` ของ sharp ไม่ได้อยู่ในหน่วยเดียวกัน** จึงไม่พึ่งการตัดบรรทัด
   ของ sharp ในงานพิมพ์ — `fitLines()` ขึ้นบรรทัดเองและวัดทุกบรรทัดจริง
6. **แถบล่างที่ไม่มีอะไรอยู่ข้างในต้องหายไป ไม่ใช่เหลือเป็นแถบขาว** ค่าเริ่มต้นของ
   บูธคือไม่มีชื่องานและไม่มี QR — เห็นตอนถ่ายหน้าจอแอปจริงครั้งแรก

## ที่ยังพิสูจน์ไม่ได้จากเครื่องพัฒนา

- **โหมด CUPS ยังไม่เคยเจอเครื่องพิมพ์จริง** เทสต์ครอบได้แค่คำสั่งที่ประกอบขึ้น
  ก่อนงานต้องตรวจชื่อสื่อของรุ่นที่ใช้จริงด้วย
  `lpoptions -p <ชื่อเครื่อง> -l | grep PageSize` — ไดรเวอร์ dye-sub บางรุ่นใช้ชื่อของตัวเอง
- **สีที่ออกจากเครื่อง dye-sub ไม่ตรงกับสีบนจอ** ต้องมีรอบปรับหน้าเครื่องจริงหนึ่งรอบ
- **เกณฑ์ขนาด QR เป็นกฎทั่วไป ไม่ใช่ค่าที่วัดจากเครื่องพิมพ์ตัวนี้** ตัวตัดสินคือ
  เอากระดาษที่พิมพ์แล้วมาสแกนด้วยมือถือจริง
- **ยังไม่เคยเจอจอที่สองจริงและรีโมทจริง** เครื่องพัฒนามีจอเดียว เทสต์สองหน้าต่าง
  จึงใช้ `BOOTH_OPERATOR=1` และจำลองปุ่มรีโมทด้วยการกดคีย์บอร์ดใส่หน้าต่าง
  (ซึ่งเป็นเส้นทางเดียวกับที่รีโมทจริงเดิน เพราะมันคือคีย์บอร์ดในสายตาระบบ)
  · **การแจกจอว่าตัวไหนเป็นจอหน้า ต้องลองกับจอสองตัวจริงหนึ่งครั้ง**
- **`globalKeys` ยังไม่เคยทดสอบกับเดสก์ท็อปจริง** ปุ่มเสียงบน GNOME/KDE อาจถูกยึด
  ไว้ก่อนจนจดไม่ได้ — บูธจะพิมพ์คำเตือนบอกว่าจดปุ่มไหนไม่สำเร็จ ไม่ใช่เงียบ
