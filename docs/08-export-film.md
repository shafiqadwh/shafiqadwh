# รวมงานทั้งวันให้เป็นไฟล์หนังหนึ่งไฟล์

หลังงานจบ เอารูปกับวิดีโอที่แขกส่งมาทั้งหมดมาต่อเป็นหนังเรื่องเดียว
สำหรับเก็บไว้ดู ส่งให้ญาติ หรืออัปขึ้น YouTube

**ทำหลังงานเท่านั้น** ไม่เกี่ยวกับระบบที่ใช้หน้างาน

สั่งได้สองทาง — **กดปุ่มในหน้าแอดมิน** หรือ **รันคำสั่งผ่าน ssh** ทั้งสองทางใช้โค้ดชุดเดียวกัน
และมีล็อกกันไม่ให้รันชนกัน

---

## วิธีที่ 1 — กดปุ่มในหน้าแอดมิน (แนะนำ)

เข้า `/admin` แล้วเลื่อนลงไปที่หัวข้อ **หนังงานแต่ง**

1. ตั้งค่าได้: รูปละกี่วินาที · ตัดวิดีโอไม่เกินกี่วินาที · ซูมภาพช้า ๆ
2. อยากมีเพลงคลอ กด **เลือกไฟล์เพลง** อัพไฟล์เสียงที่มีสิทธิ์ใช้ (ไม่เกิน 30 MB)
   แล้วติ๊ก **ใส่เพลงคลอ**
3. กด **เริ่มสร้างหนัง**

แถบความคืบหน้าจะบอกว่าทำถึงคลิปที่เท่าไหร่จากทั้งหมด และเหลืออีกกี่นาที
**ปิดหน้าไปทำอย่างอื่นได้** งานรันต่อบนเซิร์ฟเวอร์ กลับมาเปิดหน้าใหม่แล้วเห็นสถานะเดิม

พอเสร็จ ตัวเล่นวีดีโอจะโผล่ขึ้นมาในหน้านั้นเลย **กดเล่นดูได้ทันที** และมีปุ่ม
**ดาวน์โหลดไฟล์** ข้างใต้ ไม่ต้องเข้า File Station หรือ SMB

หนังเก่ายังเล่นได้ตลอดแม้จะยังไม่เคยกดสร้างใหม่ — ระบบจำไว้ว่าไฟล์ล่าสุดสร้างเมื่อไหร่และใหญ่เท่าไหร่

## วิธีที่ 2 — สั่งจาก SSH

ssh เข้า NAS แล้วพิมพ์บรรทัดเดียว:

```
cd /volume1/docker/wedding-share && sudo ./scripts/export-film.sh
```

ใส่เพลงคลอด้วย (วางไฟล์เพลงไว้ในโฟลเดอร์ข้อมูลก่อน):

```
cd /volume1/docker/wedding-share && sudo ./scripts/export-film.sh --music /app/data/song.mp3
```

อยากดูผลสั้น ๆ ก่อนรันเต็ม — เอาแค่ 20 รูปแรก:

```
cd /volume1/docker/wedding-share && sudo ./scripts/export-film.sh --limit 20
```

ได้ไฟล์ที่ **`/volume1/wedding/export/wedding-film.mp4`** เปิดจาก File Station
หรือ SMB ได้เลย

## ตัวเลือก

| ตัวเลือก | ค่าเริ่มต้น | ทำอะไร |
|---|---|---|
| `--seconds N` | 6 | รูปหนึ่งใบค้างจอกี่วินาที |
| `--max-video-seconds N` | 30 | ตัดวิดีโอของแขกไม่ให้ยาวเกินกี่วินาที |
| `--music PATH` | ไม่มี | ไฟล์เพลงคลอ |
| `--motion` | ปิด | ซูมช้า ๆ แบบ Ken Burns (ช้าลงและภาพนุ่มลงนิดหน่อย) |
| `--keep-duplicates` | ปิด | ไม่ตัดไฟล์ที่อัปซ้ำออก |
| `--limit N` | ทั้งหมด | ใช้รูปแค่ N ใบแรก |
| `--out PATH` | `data/export/wedding-film.mp4` | ที่เก็บไฟล์ผลลัพธ์ |

## ในหนังมีอะไร

1. **การ์ดเปิด** — โมโนแกรม ชื่อบ่าวสาว วันที่ และสถานที่ จาก `.env` ชุดเดียวกับที่การ์ด QR ใช้
2. **รูปทุกใบ เรียงตามเวลาที่แขกส่งเข้ามาจริง** หนังจึงเดินไปตามงานเองตั้งแต่คนมาถึงจนเลิกงาน
   รูปแนวตั้งไม่มีแถบดำสองข้าง แต่ใช้ตัวมันเองเบลอเป็นพื้นหลัง เหมือนที่สไลด์โชว์ทำ
3. **วิดีโอของแขกพร้อมเสียงเดิม** ประกอบเข้าเฟรมแบบเดียวกับรูป
4. **คำอวยพร** — ที่แนบรูปมาจะไปอยู่บนรูปใบนั้น ส่วนที่ไม่แนบขึ้นเป็นการ์ดข้อความ
   โรยแทรกให้ห่างเท่า ๆ กันตลอดเรื่อง ไม่กองรวมท้ายเรื่อง
5. **การ์ดปิด** — คำขอบคุณในภาษาหลักของงาน
6. **ไม่มี QR** ตามที่เจ้าของขอ

## เรื่องที่ตัดสินใจไว้ และเหตุผล

**ตัวหนังสือเรนเดอร์ด้วย Pango ไม่ใช่ `drawtext` ของ ffmpeg**
ffmpeg ที่ติดมากับ Debian bookworm (ตัวที่อยู่ในอิมเมจนี้) ไม่ได้ build มากับ harfbuzz
`drawtext` จึงวางสระกับวรรณยุกต์ไทยด้วยการเลื่อนตำแหน่งแบบง่าย ๆ คำอย่าง
"ปี่ ญี่ปุ่น เกี๊ยะ" ออกมาเพี้ยน ซึ่งรับไม่ได้กับของที่บ่าวสาวจะเก็บไว้ดูตลอดชีวิต
จึงใช้ Pango ที่ติดมากับ `sharp` (เป็น dependency เดิมอยู่แล้ว) ซึ่งจัดรูปอักษรเต็มรูปแบบ
และรองรับ RTL กับภาษาจีนไว้ในตัวสำหรับแผนธุรกิจในอนาคต

**ฟอนต์เดินทางมากับโค้ด** อยู่ที่ `assets/fonts/` — Noto Serif Thai และ Noto Naskh Arabic
(ทั้งคู่สัญญาอนุญาต SIL OFL 1.1) เพราะอิมเมจ `node:slim` ไม่มีฟอนต์ไทยหรืออาหรับเลยสักตัว
และคอนเทนเนอร์บน NAS นี้ต่อเน็ตออกไม่ได้ วิธีนี้จึงไม่ต้อง build อิมเมจใหม่

**ฟอนต์ถูกเลือกจากตัวอักษรในข้อความจริง ไม่ใช่จากภาษาหลักของงาน**
ครูสอนภาษาอาหรับเขียนคำอวยพรเป็นภาษาอาหรับได้ แม้ภาษาหลักของงานจะเป็นไทย
หนังเรื่องเดียวกันจึงมีได้ทั้งสองอักษร ระบบจึงดูเป็นข้อความ ๆ ไป และไม่พึ่ง fallback
ของ fontconfig ซึ่งขึ้นกับว่าเครื่องนั้นมีฟอนต์อะไรติดตั้งไว้ — เครื่องพัฒนามี
แต่คอนเทนเนอร์อาจไม่มี แล้วคำอวยพรจะกลายเป็นกล่องว่างโดยไม่มี error ให้เห็น

**ทำทีละคลิปแล้วค่อยต่อ** ไม่ยัด `filter_complex` ก้อนเดียวที่มีอินพุตหลายร้อยไฟล์
ซึ่งจะเปิดไฟล์ค้างไว้พร้อมกันหมดจนแรมล้ม การต่อใช้ concat demuxer แบบ `-c copy`
คือไม่เข้ารหัสซ้ำ ไม่เสียคุณภาพ และ **รันซ้ำได้** คลิปที่ทำเสร็จแล้วจะถูกข้าม
ถ้ารันแล้วล้มกลางทาง สั่งซ้ำได้เลยไม่ต้องเริ่มใหม่

**ตัดไฟล์ซ้ำด้วยแฮชของเนื้อไฟล์จริง** ตอนแรกใช้ขนาดไฟล์บวกมิติเพราะเร็วกว่า
แล้วเทสต์จับได้ว่ารูปสีพื้นคนละสีถูกตัดทิ้งเพราะบีบอัดออกมาได้ขนาดเท่ากันพอดี
รูปงานจริงคงไม่ชนกันแบบนั้น แต่ "คงไม่" ไม่ดีพอสำหรับของที่ตัดรูปของแขกทิ้งถาวร
การอ่านไฟล์ทั้งหมดมาแฮชใช้เวลาราวสิบวินาทีต่อรูปพันใบ ซึ่งไม่มีความหมายเลย
เทียบกับเวลาเข้ารหัสทั้งเรื่อง

**สองทางเข้า ล็อกเดียว** ปุ่มในเว็บรันในคอนเทนเนอร์เดียวกับเว็บ ส่วน `export-film.sh`
รันในคอนเทนเนอร์ชั่วคราวคนละตัว สองโปรเซสนี้เช็ก PID ข้ามกันไม่ได้เลย (คนละ PID namespace)
ล็อกจึงเป็นไฟล์บนดิสก์ที่ทั้งคู่มองเห็น และใช้ "เวลาที่แตะไฟล์ล่าสุด" แทนการเช็กว่าโปรเซสยังอยู่ไหม
ถ้าไม่มีการแตะเกินหนึ่งนาที ถือว่าตายไปแล้วและปล่อยให้เริ่มใหม่ได้เอง โดยไม่ต้องมีใครมาลบไฟล์ล็อกทิ้ง

**งานที่ตายกลางทางถูกรายงานตามจริง** ถ้าคอนเทนเนอร์รีสตาร์ทตอนกำลังเรนเดอร์ ไฟล์สถานะจะยัง
ค้างว่า "กำลังทำ" อยู่ หน้าเว็บจึงตรวจด้วยว่ายังมีใครถือล็อกจริงไหม ถ้าไม่มีก็บอกว่าหยุดกลางทาง
แล้วกดเริ่มใหม่ได้ ระบบจะทำต่อจากคลิปที่ค้างไว้ ไม่เริ่มจากศูนย์

**งานจากปุ่มถูกลดความสำคัญของ CPU ลง** เพราะมันรันในคอนเทนเนอร์เดียวกับเว็บที่แขกใช้อยู่
ffmpeg ที่ถูกเรียกต่อจากโปรเซสนั้นสืบทอดค่าไปด้วย เว็บจึงยังตอบสนองระหว่างเรนเดอร์

**เพลงคลอหลบให้เสียงงานเอง** วัดครั้งแรกแล้วพบว่าช่วงภาพนิ่ง (ซึ่งคือเกือบทั้งเรื่อง)
เพลงลงไปอยู่ที่ -43 dB คือแทบไม่ได้ยิน เพราะ `amix` หารระดับเสียงตามจำนวนอินพุตอีกชั้น
ตอนนี้ปิดการหารนั้นแล้วให้เพลงดังพอฟังได้จริง ส่วนตอนที่วิดีโอของแขกมีเสียงคนพูด
เพลงจะหลบลงเองด้วย `sidechaincompress`

## ใช้เวลานานแค่ไหน

ประมาณจากงานที่มีรูปพันใบ ที่ 6 วินาทีต่อใบ → หนังยาวราว **100 นาที**
เวลาเรนเดอร์บน CPU ของ NAS ราว **40–70 นาที** รันทิ้งไว้ได้ เว็บยังทำงานปกติระหว่างนั้น
ไฟล์ผลลัพธ์ราว 3–6 GB

ถ้าอยากได้หนังสั้นลง ลด `--seconds` เหลือ 4 หรือใช้ `--max-video-seconds 15`

## ถ้ามีปัญหา

| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| `เรนเดอร์ตัวหนังสือไม่ได้` ตั้งแต่วินาทีแรก | โฟลเดอร์ `assets/` ยังไม่ได้ mount — ดึงโค้ดล่าสุดด้วย `update.sh` ก่อน |
| `ไม่พบโฟลเดอร์ข้อมูล` | ที่เก็บข้อมูลใน `docker-compose.yml` ไม่ตรงกับของจริง |
| หยุดกลางทาง | สั่งซ้ำได้เลย คลิปที่ทำเสร็จแล้วจะถูกข้าม |
| อยากเริ่มใหม่ทั้งหมด | ลบโฟลเดอร์ `/volume1/wedding/export/parts` ทิ้งก่อนรัน |
