# รวมงานทั้งวันให้เป็นไฟล์หนังหนึ่งไฟล์

หลังงานจบ เอารูปกับวิดีโอที่แขกส่งมาทั้งหมดมาต่อเป็นหนังเรื่องเดียว
สำหรับเก็บไว้ดู ส่งให้ญาติ หรืออัปขึ้น YouTube

**ทำหลังงานเท่านั้น** ไม่เกี่ยวกับระบบที่ใช้หน้างาน

สั่งได้สองทาง — **กดปุ่มในหน้าแอดมิน** หรือ **รันคำสั่งผ่าน ssh** ทั้งสองทางใช้โค้ดชุดเดียวกัน
และมีล็อกกันไม่ให้รันชนกัน

---

## วิธีที่ 1 — กดปุ่มในหน้าแอดมิน (แนะนำ)

เข้า `/admin` แล้วเลื่อนลงไปที่หัวข้อ **หนังงานแต่ง**

1. ติ๊ก **รูปแบบหนัง** — ติ๊กได้ทั้งสองแบบ **กดครั้งเดียวได้สองเรื่อง**
   (ค่าเริ่มต้นคือติ๊กไว้ทั้งคู่)
2. ดูบรรทัดที่โปรแกรมคำนวณให้ เช่น *"820 รูป · 14 วิดีโอ · โปรแกรมเลือก 4 วินาทีต่อรูป
   · หนังยาวประมาณ 61 นาที"* — **ไม่ต้องกรอกอะไร** ถ้าอยากกำหนดเองค่อยใส่ตัวเลขทับ
3. เลือกเพลงจากคลัง (ดูหัวข้อถัดไป) ติ๊กกี่เพลงก็ได้ เพลงเดิมซ้ำก็ได้
4. กด **เริ่มสร้างหนัง**

แถบความคืบหน้าจะบอกว่าทำถึงคลิปที่เท่าไหร่จากทั้งหมด และเหลืออีกกี่นาที
**ปิดหน้าไปทำอย่างอื่นได้** งานรันต่อบนเซิร์ฟเวอร์ กลับมาเปิดหน้าใหม่แล้วเห็นสถานะเดิม

พอเสร็จ ตัวเล่นวีดีโอจะโผล่ขึ้นมาในหน้านั้นเลย **กดเล่นดูได้ทันที** และมีปุ่ม
**ดาวน์โหลดไฟล์** ข้างใต้ ไม่ต้องเข้า File Station หรือ SMB

### แกลเลอรีหนัง

หนังทุกเรื่องที่เคยสร้างถูกเก็บไว้แยกกัน **ไม่ทับกัน** ใต้ฟอร์มจะมีรายการหนังทั้งหมด
เรียงจากใหม่ไปเก่า แต่ละเรื่องมีตัวเล่นของตัวเอง บอกว่าใช้รูปแบบไหน สร้างเมื่อไหร่
ขนาดเท่าไหร่ มีเพลงหรือไม่ พร้อมปุ่ม **ดาวน์โหลด** และ **ลบ**

ลองสร้างหลายแบบแล้วเทียบกันได้ พอเลือกได้แล้วค่อยลบที่ไม่เอาทิ้ง — ไฟล์หนัง
เรื่องละหลาย GB จึงไม่ควรปล่อยสะสมไว้

> คลิปย่อยระหว่างทางอยู่ที่ `data/export/parts/` **ถูกลบให้เองเมื่อหนังเสร็จครบทุกเรื่อง**
> ถ้างานล้มกลางทางจะเก็บไว้ เพื่อให้กดใหม่แล้วทำต่อจากเดิมได้ไม่ต้องเริ่มจากศูนย์

## เพลงคลอในหน้าเว็บ (คนละอันกับเพลงในหนัง)

> ⚠️ **ปุ่ม ♪ ถูกถอดออกจากหน้าแขกไปก่อน** (วางอยู่ระหว่างข้อความต้อนรับกับปุ่ม
> อัพโหลดพอดี ดูเกะกะ) ตัวเลือกในหน้าแอดมินด้านล่างยังใช้ได้ปกติ เลือกเพลงได้
> เหมือนเดิม แค่ยังไม่มีที่ไหนแสดงผลให้แขกเห็น — เอาปุ่มกลับมาได้ด้วยการ
> `git revert` คอมมิตที่ถอดมันออก โดยไม่ต้องเลือกเพลงใหม่

หน้าแอดมิน → **เพลงคลอในหน้าเว็บ** → เลือกเพลงจากคลังเดียวกับที่หนังใช้ → บันทึก
เลือก "ไม่เปิดเพลง" เมื่อไหร่ก็ปิดได้ ค่าเริ่มต้นคือปิด

**แขกต้องกดปุ่ม ♪ เองถึงจะเล่น** และนี่เป็นการตัดสินใจ ไม่ใช่ข้อจำกัด

| เหตุผล | รายละเอียด |
|---|---|
| เบราว์เซอร์บล็อกอยู่แล้ว | เสียงที่เล่นเองโดยไม่มีการกดถูกปฏิเสธทุกเบราว์เซอร์สมัยใหม่ |
| **แบนด์วิดท์ของบ้าน** | เพลงในคลังเฉลี่ย **4.8 MB** (2.4–8.3 MB) · แขก 1,000 คนเปิดคนละครั้ง = **~4.7 GB ขาออก** ซึ่งต้องแบ่งกับ *การอัพรูป* ที่เป็นงานหลักของระบบ · เปิดเองอัตโนมัติ = จ่ายค่านี้ให้ทุกคน รวมคนที่ไม่ได้อยากฟัง |
| ปิดเสียงในงานจริง | ในงานเลี้ยงเสียงดังอยู่แล้ว คนที่อยากฟังคือคนที่เปิดดูรูปทีหลังที่บ้าน |

`preload="none"` ทำให้ไฟล์ถูกโหลด **เฉพาะตอนกด** (วัดแล้วด้วยเบราว์เซอร์จริง: ก่อนกด
มีคำขอไฟล์เสียง 0 ครั้ง) · เพลงวนไปเรื่อย ๆ ที่ระดับเสียง 35% · ใครเคยเปิดไว้แล้วเปิดหน้าใหม่
โปรแกรมจะลองเล่นต่อให้ ถ้าเบราว์เซอร์ไม่ยอมก็แค่ค้างที่ปุ่ม "เปิดเพลง" ตามเดิม ไม่มีอะไรพัง

ไฟล์เพลงถูกลบทีหลัง (เช่นลบจาก File Station) → **ปุ่มหายไปจากหน้าเว็บเอง** ไม่ใช่ปุ่มที่กดแล้วเงียบ

## เพลงคลอ

### คลังเพลงที่มากับโปรแกรม

เพลงไม่ได้อยู่ใน git เพราะ `scripts/update.sh` โหลดโค้ดทั้งก้อนใหม่ทุกครั้งที่อัปเดต
ไฟล์เสียงร้อยเมกะไบต์จะถูกลากมาซ้ำทุกครั้งไปตลอด ทั้งที่โหลดครั้งเดียวก็พอ
โหลดเข้าคลังด้วยคำสั่งเดียวบน NAS

```bash
cd /volume1/docker/wedding-share
sudo ./scripts/fetch-music.sh          # ~105 MB · รันซ้ำได้ ของที่มีแล้วจะถูกข้าม
sudo ./scripts/fetch-music.sh --list   # ดูรายชื่อก่อน ไม่โหลด
```

สคริปต์หาโฟลเดอร์ข้อมูลเองจากคอนเทนเนอร์ที่รันอยู่ ถ้าหาไม่เจอจะใช้ `/volume1/wedding`
และถ้าโฟลเดอร์นั้นไม่มีจริงมันจะ**หยุดพร้อมบอกว่าคาดว่าอยู่ที่ไหน** ไม่ใช่โหลดลงที่ผิด
เงียบ ๆ (เพลงต้องอยู่โฟลเดอร์เดียวกับที่แอปอ่าน ไม่งั้นโหลดเสร็จแล้วคลังจะว่างเปล่า)
โฟลเดอร์ข้อมูลอยู่ที่อื่นให้สั่ง `--data-dir /path/ถึงโฟลเดอร์ข้อมูล`

archive.org กระจายไฟล์ไว้หลายโหนดและบางโหนดตอบ **500 หรือ 502 เป็นพัก ๆ** เป็นเรื่องปกติ
ของบริการนี้ ไม่ใช่ว่าไฟล์หาย สคริปต์จึงลองใหม่ให้เองสามครั้ง เว้นครั้งละสามวินาที
ถ้าเจอโหนดที่ล่มยาวกว่านั้น สคริปต์จะจบด้วยรหัส 1 พร้อมบอกว่าเหลือกี่เพลง —
**รันซ้ำได้เลย เพลงที่โหลดครบและแฮชตรงแล้วจะถูกข้าม** (ไฟล์ที่โหลดไม่ครบถูกทิ้งไปแล้ว
ไม่ค้างมาให้ ffmpeg ไปล้มทีหลัง)

โฟลเดอร์คลังถูกสร้างโดย `fetch-music.sh` เอง ซึ่งต้องรันด้วย `sudo` — ไฟล์ที่ curl/mv
สร้างขึ้นจึงเป็นของ **root** โดยธรรมชาติ ไม่ใช่ของผู้ใช้ที่คอนเทนเนอร์รันอยู่จริง
(`PUID`/`PGID` ใน `.env`) `ls /volume1/wedding/music/library` จากบัญชี DSM ปกติเลย
ขึ้น `Permission denied` เป็นเรื่องปกติ ใช้ `sudo ls`

**แต่ `sudo ls` เห็นไฟล์ครบไม่ได้แปลว่าคอนเทนเนอร์อ่านได้** — root มองเห็นทุกอย่างเสมอ
ส่วนคอนเทนเนอร์รันเป็น `PUID:PGID` เท่านั้น ถ้าสองอย่างนี้ไม่ตรงกัน `fs.readdir()`
ในคอนเทนเนอร์จะเจอ `EACCES` แล้ว **คลังเพลงว่างเปล่าในหน้าเว็บทั้งที่สคริปต์เพิ่งบอกว่า
โหลดสำเร็จครบทุกเพลง** — ตั้งแต่เวอร์ชันนี้ `fetch-music.sh` chown ไฟล์ให้เป็นของ
`PUID:PGID` เองหลังโหลดเสร็จทุกครั้งแล้ว ถ้าเคยโหลดด้วยเวอร์ชันเก่ามาก่อนหน้านี้ แก้ครั้งเดียวด้วย

```bash
sudo chown -R 1026:100 /volume1/wedding/music
```

(ตัวเลขต้องตรงกับ `PUID`/`PGID` ใน `.env` จริง — ค่าเริ่มต้นตาม `.env.example` คือ
`1026:100`) หรือรัน `sudo ./scripts/diagnose-nas.sh` — ข้อ **3.6** ตรวจให้เองว่า
คอนเทนเนอร์อ่านคลังเพลงได้จริงไหม พร้อมบอกคำสั่งแก้ถ้าไม่ได้

| กลุ่ม | เพลง | เหมาะกับ |
|---|---|---|
| งานแต่งงาน | Nocturne / Waltz / Prelude ของโชแปง | บรรยากาศอ่อนโยน |
| งานรับปริญญา | Polonaise ของโชแปง | จังหวะสง่า เดินขบวน |
| งานวันเกิด | Waltz / Mazurka ที่สั้นและสดใส | บรรยากาศครึกครื้น |
| บรรเลงเบา ๆ | Prelude / Nocturne ที่เงียบกว่า | คลอเบา ๆ ไม่แย่งความสนใจ |

ทั้งหมดเป็นบันทึกเสียงสาธารณสมบัติจาก **Musopen** บน archive.org สัญญาอนุญาต
**CC0 1.0** — ใช้ได้ทุกกรณีรวมถึงงานที่มีรายได้ **ไม่ต้องให้เครดิต** ที่มาของทุกเพลง
พร้อมค่าแฮชอยู่ใน `assets/music-catalogue.json` สคริปต์ตรวจแฮชทุกไฟล์ ไม่ตรงคือทิ้ง

> ⚠️ **ฟังก่อนใช้จริง** เพลงชุดนี้ถูกคัดจากข้อมูลกำกับ (ชื่อเพลง ประเภท ความยาว)
> ไม่ได้ถูกฟังมาก่อน เพลงไหนไม่เข้ากับงาน ลบไฟล์ทิ้งจาก `data/music/library/` ได้เลย
> หรือลบรายการออกจาก `assets/music-catalogue.json` ไม่ให้โหลดกลับมาอีก

### เพลงของตัวเอง

กด **เลือกไฟล์เพลง** ในหน้าแอดมิน ไฟล์จะไปอยู่ในกลุ่ม **เพลงของฉัน** ปนกับกลุ่มอื่นได้
อัพกี่เพลงก็ได้ ลบรายเพลงได้ **เจ้าของต้องมีสิทธิ์ใช้เพลงนั้นเอง**

### หนึ่งเรื่อง หลายเพลง

ติ๊กกี่เพลงก็ได้ ระบบต่อให้เป็นเส้นเดียวตามลำดับที่ติ๊ก แล้ว**ไล่เฟดทับกันตรงรอยต่อ**
ไม่ใช่ต่อดื้อ ๆ — วัดจริงแล้วการต่อดื้อ ๆ ทำให้มีความเงียบ 3.5–5.3 วินาทีคาอยู่ทุกครั้ง
ที่เปลี่ยนเพลง เพราะเพลงเปียโนจบด้วยเสียงที่ค่อย ๆ หายไป

- เลือกเพลงยาวรวม **ไม่พอ** ทั้งเรื่อง → วนเพลย์ลิสต์เดิมต่อจนจบ (รอยวนก็ถูกเฟดทับด้วย)
- เลือก **เพลงเดียว** → วนเพลงนั้นทั้งเรื่อง
- เลือก **เพลงซ้ำ** ได้ ระบบไม่ยุบของซ้ำทิ้ง
- **ไม่เลือกเลย** → หนังเงียบ (เสียงในวิดีโอของแขกยังอยู่ครบ)
- เพลงสั้นกว่า 4 วินาที ระบบหดเวลาเฟดให้พอดีเอง · สั้นกว่า 1.5 วินาทีจะถูกปฏิเสธ
  พร้อมบอกเหตุผล (สั้นเกินกว่าจะเชื่อมต่อกันให้ฟังรู้เรื่องได้)

แถบใต้รายการบอกตลอดว่าเลือกไปแล้วกี่นาที จากที่ต้องการกี่นาที

## ความยาวหนัง — โปรแกรมคิดให้เอง

ไม่ต้องกรอกว่ารูปละกี่วินาที โปรแกรมดูจากจำนวนรูปแล้วเลือกให้ โดยคุมไว้ใน**ช่วง 4–8 วินาที**

| จำนวนรูป | วินาทีต่อใบ |
|---|---|
| ไม่เกิน 40 | 8 |
| 41–120 | 7 |
| 121–300 | 6 |
| 301–700 | 5 |
| เกิน 700 | 4 |

ต่ำกว่าสี่วินาทีคนดูไม่ทันว่าในรูปมีใคร สูงกว่าแปดวินาทีรูปเดียวก็เริ่มน่าเบื่อ
วิดีโอของแขกนับตามความยาวจริง (ตัดที่เพดานที่ตั้งไว้) การ์ดคำอวยพรมีเวลาอ่านขั้นต่ำของมันเอง

ตัวเลขที่โชว์คือตัวเลขที่ใช้จริง — **หนังสองเรื่องจากปุ่มเดียวยาวเท่ากันเป๊ะและใช้เพลงชุดเดียวกัน**
เพราะความยาวกับเพลงถูกคิดครั้งเดียวแล้วใช้ร่วมกัน

## สองรูปแบบ

| | **โรงหนัง** | **กำแพงรูป** |
|---|---|---|
| หน้าตา | รูปเดียวเต็มจอ พื้นหลังเป็นรูปเดิมเบลอ | โพลารอยด์กระจายทั้งจอ ใบกลางสว่างขึ้นมา ใบอื่นหรี่ |
| วิดีโอของแขก | เต็มจอ พร้อมเสียงเดิม | **เล่นอยู่ในกรอบโพลารอยด์** พร้อมเสียงเดิม |
| คำอวยพร | การ์ดข้อความเต็มจอ | การ์ดข้อความเต็มจอเหมือนกัน |
| เหมาะกับ | ดูรูปทีละใบชัด ๆ | ให้เห็นบรรยากาศรวมของงาน |

การ์ดเปิดกับการ์ดปิดเหมือนกันทั้งสองแบบ

## วิธีที่ 2 — สั่งจาก SSH

ssh เข้า NAS แล้วพิมพ์บรรทัดเดียว:

```
cd /volume1/docker/wedding-share && sudo ./scripts/export-film.sh
```

ใส่เพลงคลอด้วย (วางไฟล์เพลงไว้ในโฟลเดอร์ข้อมูลก่อน):

```
cd /volume1/docker/wedding-share && sudo ./scripts/export-film.sh --music /app/data/song.mp3
```

อยากดูผลสั้น ๆ ก่อนรันเต็ม — เอาแค่ 20 รูปแรก:

```
cd /volume1/docker/wedding-share && sudo ./scripts/export-film.sh --limit 20
```

ได้ไฟล์ในโฟลเดอร์ **`/volume1/wedding/export/films/`** เปิดจาก File Station หรือ SMB
ได้เลย และจะขึ้นในแกลเลอรีหน้าแอดมินด้วย

## ตัวเลือก

| ตัวเลือก | ค่าเริ่มต้น | ทำอะไร |
|---|---|---|
| `--seconds N` | อัตโนมัติ | รูปหนึ่งใบค้างจอกี่วินาที (ไม่ใส่ = ให้โปรแกรมคิดจากจำนวนรูป) |
| `--max-video-seconds N` | 30 | ตัดวิดีโอของแขกไม่ให้ยาวเกินกี่วินาที |
| `--music PATH` | ไม่มี | ไฟล์เพลงคลอ |
| `--motion` | ปิด | ซูมช้า ๆ แบบ Ken Burns (ช้าลงและภาพนุ่มลงนิดหน่อย) |
| `--keep-duplicates` | ปิด | ไม่ตัดไฟล์ที่อัปซ้ำออก |
| `--limit N` | ทั้งหมด | ใช้รูปแค่ N ใบแรก |
| `--out PATH` | `data/export/films/film-<เวลา>-<รูปแบบ>.mp4` | ที่เก็บไฟล์ผลลัพธ์ |

## ในหนังมีอะไร

1. **การ์ดเปิด** — โมโนแกรม ชื่อบ่าวสาว วันที่ และสถานที่ จาก `.env` ชุดเดียวกับที่การ์ด QR ใช้
2. **รูปทุกใบ เรียงตามเวลาที่แขกส่งเข้ามาจริง** หนังจึงเดินไปตามงานเองตั้งแต่คนมาถึงจนเลิกงาน
   รูปแนวตั้งไม่มีแถบดำสองข้าง แต่ใช้ตัวมันเองเบลอเป็นพื้นหลัง เหมือนที่สไลด์โชว์ทำ
3. **วิดีโอของแขกพร้อมเสียงเดิม** ประกอบเข้าเฟรมแบบเดียวกับรูป
4. **คำอวยพร** — ที่แนบรูปมาจะไปอยู่บนรูปใบนั้น ส่วนที่ไม่แนบขึ้นเป็นการ์ดข้อความ
   โรยแทรกให้ห่างเท่า ๆ กันตลอดเรื่อง ไม่กองรวมท้ายเรื่อง
5. **การ์ดปิด** — คำขอบคุณในภาษาหลักของงาน
6. **ไม่มี QR** ตามที่เจ้าของขอ

## เรื่องที่ตัดสินใจไว้ และเหตุผล

**ตัวหนังสือเรนเดอร์ด้วย Pango ไม่ใช่ `drawtext` ของ ffmpeg**
ffmpeg ที่ติดมากับ Debian bookworm (ตัวที่อยู่ในอิมเมจนี้) ไม่ได้ build มากับ harfbuzz
`drawtext` จึงวางสระกับวรรณยุกต์ไทยด้วยการเลื่อนตำแหน่งแบบง่าย ๆ คำอย่าง
"ปี่ ญี่ปุ่น เกี๊ยะ" ออกมาเพี้ยน ซึ่งรับไม่ได้กับของที่บ่าวสาวจะเก็บไว้ดูตลอดชีวิต
จึงใช้ Pango ที่ติดมากับ `sharp` (เป็น dependency เดิมอยู่แล้ว) ซึ่งจัดรูปอักษรเต็มรูปแบบ
และรองรับ RTL กับภาษาจีนไว้ในตัวสำหรับแผนธุรกิจในอนาคต

**ฟอนต์เดินทางมากับโค้ด** อยู่ที่ `assets/fonts/` — Noto Serif Thai และ Noto Naskh Arabic
(ทั้งคู่สัญญาอนุญาต SIL OFL 1.1) เพราะอิมเมจ `node:slim` ไม่มีฟอนต์ไทยหรืออาหรับเลยสักตัว
และคอนเทนเนอร์บน NAS นี้ต่อเน็ตออกไม่ได้ วิธีนี้จึงไม่ต้อง build อิมเมจใหม่

**ฟอนต์ถูกเลือกจากตัวอักษรในข้อความจริง ไม่ใช่จากภาษาหลักของงาน**
ครูสอนภาษาอาหรับเขียนคำอวยพรเป็นภาษาอาหรับได้ แม้ภาษาหลักของงานจะเป็นไทย
หนังเรื่องเดียวกันจึงมีได้ทั้งสองอักษร ระบบจึงดูเป็นข้อความ ๆ ไป และไม่พึ่ง fallback
ของ fontconfig ซึ่งขึ้นกับว่าเครื่องนั้นมีฟอนต์อะไรติดตั้งไว้ — เครื่องพัฒนามี
แต่คอนเทนเนอร์อาจไม่มี แล้วคำอวยพรจะกลายเป็นกล่องว่างโดยไม่มี error ให้เห็น

**ทำทีละคลิปแล้วค่อยต่อ** ไม่ยัด `filter_complex` ก้อนเดียวที่มีอินพุตหลายร้อยไฟล์
ซึ่งจะเปิดไฟล์ค้างไว้พร้อมกันหมดจนแรมล้ม การต่อใช้ concat demuxer แบบ `-c copy`
คือไม่เข้ารหัสซ้ำ ไม่เสียคุณภาพ และ **รันซ้ำได้** คลิปที่ทำเสร็จแล้วจะถูกข้าม
ถ้ารันแล้วล้มกลางทาง สั่งซ้ำได้เลยไม่ต้องเริ่มใหม่

**ตัดไฟล์ซ้ำด้วยแฮชของเนื้อไฟล์จริง** ตอนแรกใช้ขนาดไฟล์บวกมิติเพราะเร็วกว่า
แล้วเทสต์จับได้ว่ารูปสีพื้นคนละสีถูกตัดทิ้งเพราะบีบอัดออกมาได้ขนาดเท่ากันพอดี
รูปงานจริงคงไม่ชนกันแบบนั้น แต่ "คงไม่" ไม่ดีพอสำหรับของที่ตัดรูปของแขกทิ้งถาวร
การอ่านไฟล์ทั้งหมดมาแฮชใช้เวลาราวสิบวินาทีต่อรูปพันใบ ซึ่งไม่มีความหมายเลย
เทียบกับเวลาเข้ารหัสทั้งเรื่อง

**กำแพงในหนังประกอบขึ้นเอง ไม่ใช่การอัดหน้าจอ** ในคอนเทนเนอร์ไม่มีเบราว์เซอร์ และการอัดจอ
แบบเรียลไทม์แปลว่าต้องรอเท่าความยาวหนังจริง ๆ เฟรมกำแพงจึงถูกประกอบด้วย `sharp` ทีละเฟรม
ซึ่งเร็วกว่าและคมกว่า ส่วนวิดีโอที่ต้องเล่นอยู่ในกรอบใช้วิธีเจาะรูโปร่งใสตรงช่องรูปของ
ใบไฮไลท์ แล้วให้ ffmpeg วางวิดีโอไว้ข้างหลังและเอาเฟรมทับลงไป ภาพจึงทะลุขึ้นมาเฉพาะในกรอบ

**คลิปย่อยแยกโฟลเดอร์ตามรูปแบบ** ไม่งั้นคลิปของโหมดโรงหนังจะถูกเอาไปใช้ซ้ำในหนังโหมด
กำแพงเพราะชื่อไฟล์ชนกันพอดี แล้วได้หนังที่ปนกันสองแบบ

**สองทางเข้า ล็อกเดียว** ปุ่มในเว็บรันในคอนเทนเนอร์เดียวกับเว็บ ส่วน `export-film.sh`
รันในคอนเทนเนอร์ชั่วคราวคนละตัว สองโปรเซสนี้เช็ก PID ข้ามกันไม่ได้เลย (คนละ PID namespace)
ล็อกจึงเป็นไฟล์บนดิสก์ที่ทั้งคู่มองเห็น และใช้ "เวลาที่แตะไฟล์ล่าสุด" แทนการเช็กว่าโปรเซสยังอยู่ไหม
ถ้าไม่มีการแตะเกินหนึ่งนาที ถือว่าตายไปแล้วและปล่อยให้เริ่มใหม่ได้เอง โดยไม่ต้องมีใครมาลบไฟล์ล็อกทิ้ง

**งานที่ตายกลางทางถูกรายงานตามจริง** ถ้าคอนเทนเนอร์รีสตาร์ทตอนกำลังเรนเดอร์ ไฟล์สถานะจะยัง
ค้างว่า "กำลังทำ" อยู่ หน้าเว็บจึงตรวจด้วยว่ายังมีใครถือล็อกจริงไหม ถ้าไม่มีก็บอกว่าหยุดกลางทาง
แล้วกดเริ่มใหม่ได้ ระบบจะทำต่อจากคลิปที่ค้างไว้ ไม่เริ่มจากศูนย์

**งานจากปุ่มถูกลดความสำคัญของ CPU ลง** เพราะมันรันในคอนเทนเนอร์เดียวกับเว็บที่แขกใช้อยู่
ffmpeg ที่ถูกเรียกต่อจากโปรเซสนั้นสืบทอดค่าไปด้วย เว็บจึงยังตอบสนองระหว่างเรนเดอร์

**เพลงคลอหลบให้เสียงงานเอง** วัดครั้งแรกแล้วพบว่าช่วงภาพนิ่ง (ซึ่งคือเกือบทั้งเรื่อง)
เพลงลงไปอยู่ที่ -43 dB คือแทบไม่ได้ยิน เพราะ `amix` หารระดับเสียงตามจำนวนอินพุตอีกชั้น
ตอนนี้ปิดการหารนั้นแล้วให้เพลงดังพอฟังได้จริง ส่วนตอนที่วิดีโอของแขกมีเสียงคนพูด
เพลงจะหลบลงเองด้วย `sidechaincompress`

## ใช้เวลานานแค่ไหน

ประมาณจากงานที่มีรูปพันใบ ที่ 6 วินาทีต่อใบ → หนังยาวราว **100 นาที**
เวลาเรนเดอร์บน CPU ของ NAS ราว **40–70 นาที** รันทิ้งไว้ได้ เว็บยังทำงานปกติระหว่างนั้น
ไฟล์ผลลัพธ์ราว 3–6 GB

ถ้าอยากได้หนังสั้นลง ลด `--seconds` เหลือ 4 หรือใช้ `--max-video-seconds 15`

## ถ้ามีปัญหา

| อาการ | สาเหตุที่พบบ่อย |
|---|---|

| อยากเริ่มใหม่ทั้งหมด | ลบโฟลเดอร์ `/volume1/wedding/export/parts` ทิ้งก่อนรัน |
| ดิสก์เริ่มเต็ม | ลบหนังเก่าที่ไม่เอาแล้วจากแกลเลอรีในหน้าแอดมิน |
