## 10.2 · กติกาที่ทำให้โปรเจกต์นี้ยังไม่พัง

ห้าข้อนี้ไม่ใช่ความชอบส่วนตัว ทุกข้อมาจากความเสียหายที่เกิดขึ้นจริงมาแล้ว

1. **เทสต์ใหม่ทุกข้อต้องล้มกับโค้ดเก่าก่อน** ถ้าทำให้มันล้มไม่ได้ แปลว่ามันไม่ได้
   ตรวจอะไร — ลบทั้งเทสต์และโค้ดที่แก้ทิ้ง อย่าเก็บไว้ให้ดูเหมือนมีคนดูแล
2. **ยืนยันด้วยผลลัพธ์ ไม่ใช่ด้วยการที่ไม่มี error** สคริปต์ที่ขึ้น ✓ แต่ยิงแค่
   `127.0.0.1` เคยบอกว่าทุกอย่างปกติในวันที่เว็บเข้าไม่ได้จากข้างนอกทั้งวัน
3. **วัดก่อนเชื่อ** ตัวเลขทุกตัวในโค้ดกับเอกสารนี้มาจากการวัดจริง ไม่ใช่การประมาณ
   (ขนาดต่อรอบ เวลาตรวจ GPU เวลาที่ใช้ประกอบแผ่น)
4. **ความผิดพลาดที่เอากลับไม่ได้สำคัญกว่าความผิดพลาดที่ลองใหม่ได้** — รูปของแขก
   ไปอยู่ในมือคนอื่น · เงินที่รับแล้วแต่ตั๋วหาย · รอบที่จดว่าส่งแล้วทั้งที่ไม่ได้ส่ง
   สามอย่างนี้ยอมให้เกิดไม่ได้แม้แต่ครั้งเดียว ส่วน "ล้มแล้วกดใหม่" ยอมได้ตลอด
5. **ห้ามใส่ backtick ในคอมเมนต์ที่อยู่ในเทมเพลตสตริง SQL** เกิดมาแล้วสามครั้ง
   ผลคือ `SyntaxError` ที่ชี้ไปคนละบรรทัดกับที่ผิดจริง

และข้อที่เป็นเรื่องกฎหมาย: **ห้ามใช้ไฟล์กรอบบูธถ่ายรูปที่แจกกันบน Instagram/X**
เกือบทั้งหมดเขียนกำกับว่าห้ามใช้เชิงพาณิชย์ งานนี้ตั้งใจขาย · เอฟเฟคทุกตัวใน
`photobooth/src/core/effects.js` จึงประกอบจากการปรับค่าสีล้วน ไม่มีไฟล์ภาพของใคร

## 10.3 · ปล่อยของขึ้นเครื่องจริง

```
cd /volume1/docker/wedding-share
```
```
sudo ./scripts/backup-zip.sh
```
```
sudo ./scripts/update.sh
```

หนึ่งคำสั่งต่อหนึ่งบรรทัดเสมอ — วางหลายบรรทัดพร้อมกันแล้ว `sudo` เด้งถามรหัส
ตรงกลาง บรรทัดถัดไปจะถูกดูดไปเป็นคำตอบของช่องรหัส **แล้วรหัสโผล่เป็นข้อความ
ธรรมดา** เกิดมาแล้วสองครั้งในโปรเจกต์นี้

`update.sh` ตัดสินเองว่าจะรีสตาร์ทเฉย ๆ (เร็ว ไม่ตัดการเชื่อมต่อของแขก) หรือสร้าง
คอนเทนเนอร์ใหม่ (เมื่อไฟล์ compose เปลี่ยน) · เว็บล่มเมื่อไรใช้

```
sudo ./scripts/ensure-up.sh
```

ซึ่งลอง GPU ก่อนแล้วถอยเป็น CPU ให้เอง · มีงานใน DSM Task Scheduler สองรายการ
เรียกมันให้อยู่แล้ว (ตอนบูต และทุก 5 นาที) **ยืนยันแล้วว่าทำงานจริงทั้งคู่**
เมื่อ 9 ก.ย. — ดูล็อกที่ `/volume1/wedding/ensure-up.log` (ต้อง `sudo cat`)

### กับดักที่เสียเวลาไปแล้วและจะเสียอีกถ้าลืม

| กับดัก | อาการ |
|---|---|
| `docker compose restart` **ไม่อ่านไฟล์ compose ใหม่** | อัปเดตขึ้น ✓ ทุกบรรทัดแล้วเว็บล่ม |
| Task Scheduler: `Start time` = `Last run time` | หน้าต่างเวลายุบเหลือรอบเดียว ตาข่ายไม่รับอะไรเลย |
| Triggered Task ไม่มีแท็บ Schedule | เห็นแท็บนั้นเมื่อไร = กดผิดเมนูมา |
| ไดรเวอร์ GPU มาช้ากว่าตาข่ายตอนบูต | เว็บขึ้นด้วย CPU ทั้งวัน ซึ่งปกติ ไม่ใช่ความเสียหาย |

## 10.4 · อะไรพิสูจน์แล้ว อะไรยัง

**พิสูจน์บนของจริงแล้ว** — เว็บรับแขกจริงทั้งงาน · สไลด์โชว์บนทีวี · GPU เข้ารหัส
วิดีโอในคอนเทนเนอร์ · ตาข่ายกู้เว็บทั้งสองงาน (ดึงปลั๊กจริง เว็บกลับมาเองใน 27 วินาที
โดยไม่มีใครสั่ง) · คลังเพลง 22 เพลงบน NAS · การอัปเดตโค้ดขึ้นเครื่องจริง

**ยังไม่เคยพิสูจน์เลยแม้แต่ครั้งเดียว** — ทั้งหมดนี้อยู่ฝั่ง Photo Booth

| เรื่อง | ทำไมเทสต์ตอบแทนไม่ได้ |
|---|---|
| **สั่งพิมพ์จริง** | เครื่องที่พัฒนาไม่มีเครื่องพิมพ์ · เทสต์ตรวจได้แค่ว่าคำสั่งที่ประกอบขึ้นถูกรูปแบบ |
| **QR พร้อมเพย์** | โปรแกรมไม่มีทางรู้ว่าเงินเข้า · **เจ้าของต้องสแกนด้วยแอปธนาคารจริงหนึ่งครั้งก่อนเปิดขาย** |
| **กล้อง DSLR ต่อสาย** | ต้องมี D7000 เสียบจริง (ตั้งเลนส์เป็น MF ก่อน ไม่งั้นล้มเพราะโฟกัสไม่เข้า) |
| **สคริปต์ PowerShell สองตัว** | เครื่องพัฒนาเป็น Linux **ไม่มี PowerShell ให้รันด้วยซ้ำ** |

สมุดบัญชีของบูธจดว่า **"มีคนกดยืนยันว่าได้รับเงินแล้ว"** ไม่ใช่ "ธนาคารแจ้งว่าเงินเข้า"
เขียนไว้ตรงตามนั้นทั้งในโค้ดและบนจอ อย่าไปทำให้มันดูเหมือนยอดที่ธนาคารรับรอง

## 10.5 · เจ็ดข้อที่แก้ไปในรอบสุดท้าย

รีวิวจากเครื่องมืออื่นเข้ามา 7 ข้อ ตรวจกับโค้ดจริงทีละข้อ — **หกข้อจริงตามที่เขียน
หนึ่งข้อจริงครึ่งเดียว** ทุกข้อที่แก้มีเทสต์ที่ล้มจริงกับโค้ดเดิม

| อาการ | ความเสียหายถ้าไม่แก้ |
|---|---|
| Dockerfile ไม่ COPY `shared/` | **อิมเมจใหม่เปิดเว็บไม่ขึ้นเลย** ไม่ใช่แค่ export หนังพัง |
| กุญแจบูธถูกตรวจหลัง multer เขียนไฟล์ | คำขอที่ไม่มีกุญแจเขียนลงดิสก์ได้ 250 MB ต่อครั้ง |
| ตัวส่งเชื่อ HTTP 200 เปล่า ๆ | หน้าล็อกอิน WiFi ตอบ 200 → จดว่าส่งแล้วทั้งที่ไม่มีอะไรขึ้นเว็บ **ตลอดกาล** |
| `fetch` ไม่มี timeout | ค้างที่รอบแรก แล้วอีกหลายร้อยรอบไม่ถูกส่งโดยไม่มีอะไรบอก |
| ปลายทางอ่านจากค่าตั้ง "ตอนกดส่ง" | รูปของลูกค้ารายหนึ่งขึ้นอัลบั้มของอีกราย |
| สองคำขอโทเคนเดียวกัน | สายที่สองลบไฟล์ที่สายแรกเพิ่งบันทึกแถวไว้ |
| กลุ่มเพลง "ของฉัน" เป็นของกลาง | งาน ก. ลบเพลงของงาน ข. ได้ (คลัง CC0 ใช้ร่วมกัน**โดยตั้งใจ** อันนั้นไม่ใช่บั๊ก) |

และเจอเองอีกสามข้อระหว่างทาง: ไฟดับหลังรับเงินแล้วตั๋วหาย · แขกเดินจากไปแล้ว
**QR ของคนก่อนค้างบนจอให้คนถัดไปสแกน** · ไม่มีอะไรเตือนก่อนดิสก์เต็ม

## 10.6 · ค้างอยู่ เรียงตามความสำคัญ

**1 · หมุนโทเคน Cloudflare** — โทเคนหลุดเป็นข้อความธรรมดาในแชทตอนก็อปผลของ
`set-config.sh --show` มาถาม (ตัวสคริปต์แก้ให้ปิดค่าแล้ว แต่โทเคนที่หลุดไปแล้ว
ยังใช้ได้อยู่) · เข้า Cloudflare → Profile → API Tokens แล้วสร้างใหม่
**ข้อนี้เป็นเรื่องความปลอดภัย ไม่ใช่งานบำรุงรักษา**

**2 · ย้าย ZIP สำรองออกจาก NAS** — สคริปต์เตือนเองทุกครั้งว่าสำเนาบนดิสก์ก้อน

**3 · ทดสอบฝั่งบูธกับของจริง** ตามตารางในข้อ 10.4 · เรียงตามที่จะเจอปัญหาก่อน:
พิมพ์ → พร้อมเพย์ → สคริปต์ Windows → กล้องใหญ่

**4 · งานเล็กที่ค้าง** — `rb.shafiq-lap.com` ยังชี้ไอพีเก่า · แอปทีวียังไม่ได้ลง

## 10.7 · งานที่ออกแบบไว้แล้วแต่ยังไม่ได้ลงมือ

> **อัปเดต 9 ก.ย.** ส่วน `auto` **เขียนเสร็จและ merge แล้ว** (คอมมิต `e28b943`)
> ของเดิมเจ็ดแบบเก็บไว้ครบตามที่เจ้าของสั่ง · เหลือเฉพาะสามแบบที่ปรับระดับได้
> ซึ่งยังติดคำถามข้อ 2 ข้างล่างอยู่
>
> สามข้อที่ตัวเลขไม่ฟ้อง เห็นตอนเรนเดอร์ออกมาดูด้วยตาเท่านั้น และเป็นเหตุผลที่
> **ห้ามเชื่อเทสต์อย่างเดียวกับงานภาพ**: `sharp.gamma()` ยกกลางภาพไม่ได้เลย ·
> auto-levels แบบตำราทำให้ภาพใต้แสงน้อย **มืดลง** · เพดานสมดุลแสงขาว ±12%
> ต่อช่องทำให้โคมไฟกลายเป็นสีฟ้า เพราะระยะห่างจริงระหว่างสองช่องคือ 27%
> รายละเอียดอยู่ในคอมเมนต์หัวไฟล์ `photobooth/src/core/auto.js`

**สามแบบที่ปรับระดับได้** ออกแบบเสร็จแล้ว ยังไม่เขียนโค้ด

สามแบบวางทับ auto อีกชั้น ปรับระดับ 0–100 โดย **ไล่ค่าพารามิเตอร์จากค่ากลาง
ไม่ใช่เบลนด์ภาพสองใบ** (เบลนด์ต้องเรนเดอร์สองรอบต่อรูปและทำให้เกรนเละ)

| แบบ | ที่ระดับเต็ม | ค่าเริ่มต้น |
|---|---|---|
| สดใส | `linear(1.10, −10)` · sat 1.14 · sharpen 0.9 | 70 |
| ฟิล์ม | `linear([0.90,0.88,0.84],[22,19,15])` · sat 0.95 · เกรน 14 | 60 |
| ขาวดำ | `recomb` ผสมช่องให้แดงหนัก (ผิวสว่าง ตำหนิจาง) ไม่ใช่ `greyscale()` | 60 |

ที่ 100% ทุกแบบดูเหมือน "ใส่ฟิลเตอร์" ที่ราว 60% ดูเหมือน "รูปสวย" ซึ่งเป็นสิ่งที่
ลูกค้าจ่ายเงินมาซื้อ

**สองข้อที่ยังไม่ได้ตัดสินและกั้นงานนี้อยู่**

1. ของเดิม 7 แบบจะเอาออก เก็บไว้ หรือย้ายไปซ่อนในหน้าตั้งค่า
2. ใครหมุนปุ่มระดับ — เจ้าของตั้งไว้ก่อนงาน หรือแขกปรับเองบนจอ
   (แนะนำให้เจ้าของตั้ง · สไลเดอร์บนจอแขกคือ 10–20 วินาทีต่อคน ซึ่งคือแถว)

**และตัดสินว่าสวยไหมต้องใช้รูปคนจริงจากบูธ** ไม่ใช่รูปสังเคราะห์ — ตัวเลขข้างบน
ตรวจได้ว่าทำในสิ่งที่อ้าง แต่ความสวยตรวจด้วยตาคนเท่านั้น
