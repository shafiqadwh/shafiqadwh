# บทที่ 5 · ดาวน์โหลดรูปทั้งหมดและสำรองข้อมูล

## 1. ดาวน์โหลดเป็น ZIP จากในเว็บ (ง่ายสุด)

`/admin` → หัวข้อ **ดาวน์โหลดทั้งหมด**

| ปุ่ม | ได้อะไร |
|---|---|
| **เฉพาะรูป (.zip)** | เฉพาะรูปนิ่ง — ไฟล์เล็ก โหลดจากมือถือได้ |
| **รูป + วิดีโอ (.zip)** | ทุกอย่าง — อาจใหญ่หลายสิบ GB **ให้โหลดจากคอมพิวเตอร์เท่านั้น** |

ภายใน ZIP จัดไว้แบบนี้

```
photos/2026-11-14-193045-Aisyah-42.jpg
videos/2026-11-14-201133-Faris-57.mov
guestbook.txt
```

- ชื่อไฟล์มี **วันเวลา + ชื่อคนส่ง + เลขไอดี** เรียงตามลำดับที่ส่งเข้ามา
- ไฟล์ในนี้เป็น **ต้นฉบับ** ที่แขกส่งมาเสมอ (ไม่ใช่รูปย่อ ไม่ใช่วิดีโอที่ถูกบีบ)
- `guestbook.txt` เก็บคำอวยพรทั้งหมดพร้อมเวลาและชื่อผู้เขียน

> ZIP ถูกสร้างแบบ stream ไม่ได้เก็บไฟล์ชั่วคราวบน NAS จึงไม่กินพื้นที่เพิ่ม
> แต่ถ้างานมีวิดีโอเยอะ การโหลดอาจใช้เวลานาน — อย่ากดยกเลิกกลางคัน

## 2. ค้นหาชื่อแขก และ PDF สองเล่ม

### ค้นหาว่าใครส่งอะไรมาบ้าง

ชื่อผู้ส่งเป็นข้อความอิสระ ไม่มีบัญชีผู้ใช้ ระบบจึงจับ "คนเดียวกัน" จากชื่อที่พิมพ์
โดยตัดหัวท้าย ยุบช่องว่างซ้ำ และไม่สนตัวพิมพ์ใหญ่เล็ก — `"สม  ชาย"` กับ `"สม ชาย"`
เป็นคนเดียวกัน ส่วน **แขกที่ไม่ระบุชื่อรวมเป็นก้อนเดียวทั้งงาน** ใช้คำว่า "ผู้ร่วมงาน"

| ที่ไหน | ทำอะไรได้ |
|---|---|
| `/admin` → **แขกในงาน** | รายชื่อทั้งหมดพร้อมจำนวนรูป/วิดีโอ/คำอวยพร · พิมพ์ในช่องเพื่อกรอง · คลิกชื่อเพื่อดูของคนนั้น |
| หน้าแกลลอรี่ | ช่องค้นหาชื่อผู้ส่ง แขกใช้เองได้เพื่อหารูปที่ตัวเองส่ง |

ลิงก์ที่ได้เป็น `/?who=<ชื่อ>` ส่งต่อให้คนอื่นได้ และช่องว่างหัวท้ายไม่ทำให้ลิงก์พัง

### PDF สองเล่ม

`/admin` → หัวข้อ **เอกสาร PDF หลังงาน** → กดปุ่มแล้วรอ ปิดหน้าไปทำอย่างอื่นได้
กลับมาเปิดใหม่จะเห็นสถานะเดิม เสร็จแล้วเปิดดูและดาวน์โหลดได้จากในหน้านั้นเลย

| เล่ม | ข้างในมีอะไร |
|---|---|
| **สมุดคำอวยพร** | คำอวยพรทุกข้อความ จัดกลุ่มตามชื่อแขก ไหลต่อกันไป พร้อมรูปที่แนบมา (ไม่มีก็ไม่ใส่) |
| **รายชื่อผู้ส่งภาพ** | ชื่อแขก + จำนวน + รูปย่อของทุกใบที่คนนั้นส่ง แบบ contact sheet |

เก็บได้หลายเล่ม ลบทีละเล่มได้ · ไฟล์อยู่ที่ `/volume1/wedding/export/papers/`
ขนาดประมาณ 200–400 KB ต่อหน้า (A4 · 150 DPI พอสำหรับพิมพ์จริง)

> **ตัวหนังสือใน PDF เลือกหรือค้นหาไม่ได้** เพราะแต่ละหน้าเป็นภาพ
> เป็นการแลกที่ตั้งใจ: ตัวหนังสือถูกเรนเดอร์ด้วย Pango ตัวเดียวกับที่ใช้ทำหนังงานแต่ง
> ซึ่งเป็นตัวเดียวที่พิสูจน์แล้วว่าวางสระกับวรรณยุกต์ไทยถูก และเรียงอาหรับขวาไปซ้ายถูก
> ไลบรารี PDF ที่จัดตัวอักษรเองจะดึงความเสี่ยงนั้นกลับมา และยังต้อง build อิมเมจใหม่
> ทุกครั้งที่อัปเดต แทนที่จะ restart เฉย ๆ

## 3. ก๊อปตรงจาก File Station (เร็วที่สุดเมื่อไฟล์เยอะมาก)

รูปทั้งหมดอยู่ที่ `/volume1/wedding/uploads` อยู่แล้ว เข้าถึงได้ 3 ทาง

- **File Station**: เลือกโฟลเดอร์ → Download (DSM บีบ ZIP ให้เอง)
- **SMB**: `\\ไอพีของ-nas\wedding` แล้วลากไฟล์ออกมา — เร็วที่สุด
- **Synology Drive / Photos**: ชี้ให้ index โฟลเดอร์นี้เพื่อดูแบบไทม์ไลน์

## 4. สคริปต์เก็บกวาดหลังงาน

```bash
cd /volume1/docker/wedding-share
sudo ./scripts/backup-zip.sh /volume1/wedding /volume1/backup
```

สคริปต์จะสร้าง 3 ไฟล์ พร้อมประทับวันที่

```
/volume1/backup/wedding-photos-2026-11-15.zip     รูปทั้งหมด
/volume1/backup/wedding-videos-2026-11-15.zip     วิดีโอทั้งหมด
/volume1/backup/wedding-db-2026-11-15.zip         ฐานข้อมูล + คำอวยพร
```

แยกเป็น 3 ไฟล์เพราะไฟล์รูปมักถูกส่งต่อให้ญาติ ส่วนวิดีโอใหญ่เกินกว่าจะแชร์ทางไลน์

**ตั้งให้รันอัตโนมัติ**: DSM → Control Panel → Task Scheduler →
Create → Scheduled Task → User-defined script

## 5. ⚠️ สำรองข้อมูลจริงจัง (ทำภายใน 24 ชม. หลังงาน)

ZIP ที่วางไว้บน NAS เครื่องเดียวกัน **ไม่ใช่การสำรองข้อมูล** — ดิสก์เสียก็หายพร้อมกัน

ทำอย่างน้อย 2 ใน 3 ข้อนี้

1. **คัดลอกลง External HDD** แล้วถอดเก็บ
2. **Hyper Backup** ขึ้นคลาวด์หรือ NAS อีกเครื่อง — เลือกโฟลเดอร์ `wedding/uploads` และ `wedding/db`
3. **อัปโหลดขึ้น Google Drive / OneDrive** ของคู่บ่าวสาว

โฟลเดอร์ `derived` ไม่ต้องสำรอง สร้างใหม่ได้จากต้นฉบับเสมอ

## 6. ประเมินพื้นที่ที่ต้องใช้

| ประเภท | ขนาดต่อไฟล์โดยประมาณ |
|---|---|
| รูปจากมือถือ | 3–5 MB |
| วิดีโอ 1 นาที (1080p) | 50–150 MB |
| วิดีโอ 1 นาที (4K) | 300–400 MB |

ตัวอย่างงาน 200 คน: รูป ~600 ใบ (≈ 3 GB) + วิดีโอ ~80 คลิป (≈ 8 GB)
รวมกับสำเนาที่แปลงแล้วอีกราว 40% → **เผื่อพื้นที่ว่างไว้ 50 GB จะสบายใจ**

**เช็คพื้นที่ก่อนวันงาน**

```bash
df -h /volume1
```

ตั้งการแจ้งเตือนที่ DSM → Control Panel → Notification เมื่อ volume ใช้เกิน 90%

ถ้าอยากจำกัดไม่ให้กินพื้นที่เกิน ให้ตั้งใน `.env`

```env
MAX_TOTAL_STORAGE_GB=50
```

เมื่อถึงลิมิต แขกจะเห็นข้อความ "พื้นที่เก็บเต็มแล้ว กรุณาแจ้งเจ้าภาพ"
ในภาษาของตัวเอง แทนที่จะเจอ error ที่ไม่รู้เรื่อง
