# 9 · หลายงานในเครื่องเดียว

เครื่องหนึ่งเครื่องรับได้หลายงานพร้อมกัน วันเดียวมีสองงานก็ได้ และงานหนึ่งกินเวลา
สามวันก็ได้ · แต่ละงานมี **โดเมนของตัวเอง รหัสแอดมินของตัวเอง ฐานข้อมูลของตัวเอง
และโฟลเดอร์ไฟล์ของตัวเอง**

> เครื่องที่ติดตั้งอยู่ก่อนหน้านี้ **ไม่ต้องทำอะไรเลย** · อัปเดตขึ้นเวอร์ชันนี้แล้ว
> งานเดิมกลายเป็น "งานเริ่มต้น" ที่ใช้ไฟล์เดิมทุกอันในที่เดิมทุกที่ ไม่มีการย้ายไฟล์
> และไม่มี migration ให้ต้องรอ

---

## 9.1 · แยกกันแค่ไหน

| | อยู่ที่ไหน |
|---|---|
| งานเริ่มต้น | `data/uploads` · `data/derived` · `data/booth` · `data/db/wedding.db` |
| งานอื่น ๆ | `data/events/<ชื่อย่อ>/uploads` · `.../db/wedding.db` · ฯลฯ |
| ทะเบียนงาน | `data/db/control.db` (มีแค่รายชื่องาน โดเมน และรหัสลูกค้าที่แฮชแล้ว) |
| คลังเพลง | `data/music` — **ใช้ร่วมกันทุกงานโดยตั้งใจ** โหลดครั้งเดียวหลายสิบเมกะไบต์ |

**แยกด้วยไฟล์ ไม่ใช่แยกด้วยเงื่อนไขในคิวรี** — คิวรีของงาน ก. ไม่ได้ "ถูกกรอง"
ออกจากข้อมูลของงาน ข. แต่มันไปไม่ถึงตั้งแต่แรกเพราะคนละไฟล์กัน · เหตุผลเต็ม ๆ
อยู่หัวไฟล์ `src/lib/tenancy.js` สรุปสั้น ๆ คือถ้าใช้คอลัมน์ `event_id` แล้วกรอง
ก็ต้องจำเงื่อนไขนั้นให้ครบทั้งห้าสิบกว่าคิวรี และลืมที่เดียวคือรูปงานแต่งของลูกค้า
รายหนึ่งไปโผล่ในแกลลอรี่ของอีกราย ซึ่งเงียบสนิทและขอโทษไม่ได้

การสำรองข้อมูลจึงง่ายไปด้วย: งานหนึ่งงาน = โฟลเดอร์เดียว ก๊อปทั้งโฟลเดอร์คือครบ

---

## 9.2 · คอนโซล — `https://<โดเมนใดก็ได้ของเครื่องนี้>/console`

เข้าด้วย **`ADMIN_PASSWORD` จาก `.env`** ซึ่งเป็นกุญแจของเจ้าของระบบ ไม่ใช่ของลูกค้า
คุกกี้คนละใบกับ `/admin` และเก็บคนละที่ — คุกกี้ของลูกค้าเปิดคอนโซลไม่ได้เด็ดขาด

หน้านี้ทำได้สี่อย่าง

1. **เปิดงานใหม่** — กรอกชื่อย่อ (a–z 0–9 ขีดกลาง) ชื่องาน โดเมน วันเริ่ม–วันสุดท้าย
   และรหัสแอดมินของลูกค้า · งานพร้อมรับแขก **ทันที** ไม่ต้องรีสตาร์ตอะไร
2. **แก้ข้อมูลงาน** — ชื่อ โดเมน ชื่อผู้ร่วมงาน สถานที่ เวลา โมโนแกรม ช่วงวันงาน
   ช่องไหนเว้นว่างจะตกกลับไปใช้ค่าจาก `.env` ให้เอง
3. **ตั้ง/ล้างรหัสแอดมินของลูกค้า** — ว่าง = ลูกค้ารายนั้นยังไม่มีรหัสของตัวเอง
4. **เก็บงานที่จบแล้วเข้าลิ้นชัก** — ข้อมูลอยู่ครบทุกอย่าง แค่ทำให้อ่านรายการง่ายขึ้น

พร้อมยอดของแต่ละงาน **แยกเป็นรายวัน** (งานสามวันต้องอ่านแยกวันได้) และยอดรวมทุกงาน

> **ไม่มีปุ่มลบงาน และจะไม่มี** · ลบงานคือลบรูปงานแต่งของลูกค้าทั้งงานในคลิกเดียว
> ปุ่มแบบนั้นไม่ควรอยู่ข้างปุ่มที่กดทุกวัน · จะลบจริงให้ลบโฟลเดอร์
> `data/events/<ชื่อย่อ>` บนเครื่องเอง ซึ่งเป็นจังหวะที่ได้คิดอีกรอบ

## 9.3 · คำขอที่เข้ามาเป็นของงานไหน

ตัดสินตามลำดับนี้

1. **โดเมนของคำขอ** — ทางหลัก · ลูกค้าแต่ละรายได้โดเมนของตัวเอง แขกที่สแกน QR
   จึงมาถึงงานที่ถูกเสมอ
2. **`?event=<ชื่อย่อ>`** — ใช้ได้เฉพาะเมื่อโดเมนที่เข้ามา **ยังไม่ได้เป็นของงานไหน**
   สำหรับงานที่ยังไม่ได้ตั้งโดเมน และสำหรับทดสอบ · เปิดครั้งแรกแล้วจำไว้ในคุกกี้
3. **งานเริ่มต้น** — ถ้าไม่เข้าเงื่อนไขไหนเลย

ข้อ 2 มีเงื่อนไข "โดเมนต้องยังไม่ถูกจอง" กำกับเพราะไม่อย่างนั้นใครก็ตามที่รู้ชื่อย่อ
ของงานอื่นจะเปิดดูงานนั้นผ่านโดเมนของลูกค้ารายนี้ได้ — **โดเมนของลูกค้าต้องหมายถึง
งานของลูกค้ารายนั้นเท่านั้น ไม่มีทางลัด**

### ตั้งโดเมนของงานใหม่บน NAS

1. Cloudflare — เพิ่ม record `rina-adam` ชี้ไปที่เดียวกับ `wedding`
   (**เมฆสีเทา ไม่ใช่สีส้ม** เหตุผลอยู่ในบทที่ 2: proxy มีเพดานอัปโหลด 100 MB
   ซึ่งจะทำให้วิดีโอของแขกส่งไม่ขึ้น)
2. DSM → Login Portal → Advanced → Reverse Proxy — เพิ่มกฎแบบเดียวกับของ `wedding`
   เปลี่ยนแค่ Source hostname · ปลายทางยังเป็น `127.0.0.1:18090` ตัวเดิม
   (คอนเทนเนอร์เดียวรับทุกงาน ไม่ต้องยกคอนเทนเนอร์ใหม่)
3. คอนโซล → แก้ไขงานนั้น → ใส่โดเมนลงช่อง "โดเมน" → บันทึก

ตรวจว่าได้ผลจริงด้วยการเปิด `https://rina-adam.example.com/` **จากมือถือที่ปิด Wi-Fi**
แล้วต้องเห็นชื่องานของลูกค้ารายนั้น ไม่ใช่ชื่องานเริ่มต้น

## 9.4 · รหัสผ่านของใครเป็นของใคร

| กุญแจ | เปิดอะไรได้ | ตั้งที่ไหน |
|---|---|---|
| `ADMIN_PASSWORD` ใน `.env` | คอนโซล **และ** หน้า `/admin` ของทุกงาน | บนเครื่อง (`scripts/set-admin-password.sh`) |
| รหัสของลูกค้าแต่ละงาน | `/admin` ของงานนั้นงานเดียว | คอนโซล |

กุญแจหลักเปิดได้ทุกงานโดยตั้งใจ — ลูกค้าลืมรหัสตอนตีสองกลางงานเกิดขึ้นจริง
และตอนนั้นไม่ใช่เวลาที่จะมานั่ง ssh เข้าเครื่อง

## 9.5 · ทีวีกับบูธ

**ทีวีจับคู่กับงาน ไม่ใช่กับเครื่อง** — เปิดแอปบนทีวีที่โดเมนของงานไหน ก็จับคู่กับ
งานนั้น (วิธีจับคู่อยู่ในบทที่ 4) · วันเดียวมีสองงานก็ใช้ทีวีคนละเครื่องคนละงานได้
หรือย้ายทีวีเครื่องเดิมข้ามงานด้วย `?pair=1` แล้วจับคู่ใหม่

**บูธก็เหมือนกัน** — `BOOTH_KEY` เป็นค่าของเครื่อง (ตัวเดียวใช้ได้ทุกงาน) แต่รอบถ่าย
จะเข้าไปอยู่ในงานที่โดเมนปลายทางชี้ไป · ตั้ง URL ในเครื่องบูธให้เป็นโดเมนของงานนั้น
ก่อนออกงาน แล้ว QR บนกระดาษที่แขกถือกลับบ้านจะพาไปหน้าที่ถูกต้อง

## 9.6 · ตรวจก่อนรับงานที่สอง

- [ ] คอนโซลเปิดได้ด้วยรหัสจาก `.env` และ **เปิดไม่ได้** ด้วยรหัสของลูกค้า
- [ ] เปิดงานใหม่จากคอนโซลแล้วอัปโหลดรูปเข้าไปได้ทันทีโดยไม่ต้องรีสตาร์ต
- [ ] `data/events/<ชื่อย่อ>/uploads` มีไฟล์ของงานนั้น และ `data/uploads` ไม่มีปนมา
- [ ] เปิดโดเมนของงานใหม่จากมือถือที่ปิด Wi-Fi แล้วเห็นชื่องานที่ถูกต้อง
- [ ] รหัสของลูกค้ารายใหม่ เข้า `/admin` ของงานอื่นไม่ได้
- [ ] จับคู่ทีวีที่โดเมนของงานใหม่ แล้วสไลด์โชว์ขึ้นรูปของงานนั้น ไม่ใช่ของงานเก่า
