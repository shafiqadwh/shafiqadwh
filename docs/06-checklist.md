## 🔗 หน้าไหนอยู่ตรงไหน

แขกเห็นแค่ 2 แท็บ (รูปภาพ / คำอวยพร) ส่วนของเจ้าภาพต้องเข้าผ่าน URL

| อยากทำอะไร | ไปที่ | หมายเหตุ |
|---|---|---|
| **ลบ / ซ่อนรูป** | `/admin` → หัวข้อ **จัดการไฟล์** | ปุ่ม **ซ่อน** และ **ลบ** อยู่ใต้รูปทุกใบ ซ่อน = เก็บไฟล์ไว้แต่ไม่แสดง, ลบ = เข้า **ถังขยะ** ก่อน (กู้คืนได้จากแบนเนอร์เลิกทำ หรือหัวข้อถังขยะท้ายหน้า) ลบไฟล์ถาวรจริงหลังผ่านไป 7 วัน (`TRASH_RETENTION_DAYS`) |
| **เลือกลบหลายรูปพร้อมกัน** | `/admin` → หัวข้อ **จัดการไฟล์** | ติ๊กเลือกได้หลายใบ แล้วกด **ลบที่เลือก** ที่แถบด้านบน — เหมือนกดลบทีละใบ กู้คืนได้เหมือนกัน |
| **ดาวน์โหลดรูปทั้งหมด** | `/admin` → หัวข้อ **ดาวน์โหลดทั้งหมด** | **เฉพาะรูป (.zip)** เบา โหลดจากมือถือได้ · **รูป + วิดีโอ (.zip)** ใหญ่มาก ให้โหลดจากคอม |
| **สไลด์โชว์ขึ้นจอ** | `/slideshow` | เปิดเต็มจอด้วย F11 · มีปุ่มลัดในหน้า `/admin` ด้วย |
| **พิมพ์การ์ด QR** | `/admin` → **การ์ด QR สำหรับพิมพ์** | เลือก **ใบต่อแผ่น** ได้ 1 / 2 / 4 · งานหลายสิบโต๊ะใช้ 4 (A6 สี่ใบต่อ A4) หรือ 2 (A5 เต็มขนาดสองใบ) · ปุ่ม PNG ไว้เอาไปทำป้ายใหญ่ |
| **เปิด/ปิดรับรูป** | `/admin` → หัวข้อ **ตั้งค่า** | ติ๊กแล้วกด **ตกลง** |
| **ลบคำอวยพร** | `/admin` → หัวข้อ **สมุดอวยพร** | ปุ่ม **ลบ** ท้ายแต่ละข้อความ |

**ทางเข้า `/admin`** มี 2 ทาง: พิมพ์ URL ต่อท้ายเอง หรือกดลิงก์ **ผู้ดูแล** เล็ก ๆ
ที่ท้ายหน้าเว็บ (แขกเห็นลิงก์นี้ได้ แต่เข้าไม่ได้ถ้าไม่มีรหัส)
พอล็อกอินแล้วจะมีแท็บ **ผู้ดูแล** โผล่ข้างบนถาวรจนกว่าจะออกจากระบบ

ระหว่างงานควร **ล็อกอิน `/admin` ค้างไว้ในมือถือเจ้าภาพก่อนงานเริ่ม**
จะได้กดลบรูปได้ทันทีโดยไม่ต้องมานั่งพิมพ์รหัสตอนชุลมุน

## ⏱ แผนเร่งด่วน (เหลือเวลาไม่ถึง 2 สัปดาห์)

จัดลำดับตามความเสี่ยง — ข้อที่พังแล้วแก้ไม่ทันให้ทำก่อน

| เมื่อไหร่ | ทำอะไร | ทำไมต้องก่อน |
|---|---|---|
| **วันนี้–พรุ่งนี้** | ติดตั้งบน NAS แล้วทดสอบใน LAN ([บทที่ 7](07-shafiq-nas.md) ขั้น 1–3) | ถ้าเจอปัญหา build หรือสิทธิ์ไฟล์ จะมีเวลาแก้ |
| **ภายใน 3 วัน** | DNS 2 ระเบียน + reverse proxy + map cert + แก้ลิมิต nginx | DNS ใช้เวลากระจาย และเป็นจุดที่พลาดบ่อยที่สุด |
| **ภายใน 4 วัน** | ทดสอบจากมือถือ **4G จริง** ทั้ง iPhone และ Android รวมวิดีโอ | ถ้าติดอะไรยังเหลือเวลาอีกสัปดาห์ |
| **ประมาณ 1 สัปดาห์ก่อน** | ใส่ค่าจริงใน `.env` แล้ว **พิมพ์การ์ด QR** | เผื่อเวลาสั่งพิมพ์/ตัด/ใส่กรอบ |
| **2–3 วันก่อน** | ซ้อมต่อจอสไลด์โชว์กับโน้ตบุ๊กเครื่องที่จะใช้จริง | จะได้รู้ว่าต้องพกอะแดปเตอร์อะไร |
| **1 วันก่อน** | ลบรูปทดสอบ เช็คพื้นที่ว่าง ล็อกอิน `/admin` ค้างในมือถือ | — |

⚠️ **ห้ามเลื่อนการพิมพ์การ์ดไปจนนาทีสุดท้าย** — `BASE_URL` ต้องนิ่งก่อนพิมพ์
ถ้าเปลี่ยน URL หลังพิมพ์แล้ว การ์ดทุกใบใช้ไม่ได้

## 🗓 1 สัปดาห์ก่อนงาน

- [ ] เว็บเปิดได้จาก **4G/5G** (ปิด Wi-Fi ทดสอบ) เห็นแม่กุญแจ 🔒
- [ ] ใบรับรอง HTTPS ยังไม่หมดอายุ — DSM → Security → Certificate ดูวันหมดอายุ
- [ ] ทดสอบอัพโหลด **รูปจาก iPhone** (ไฟล์ .HEIC ต้องขึ้นแสดงได้ปกติ)
- [ ] ทดสอบอัพโหลด **วิดีโอจาก iPhone** (.mov — ตัวที่พังบ่อยที่สุด)
- [ ] ทดสอบอัพโหลด **รูปและวิดีโอจาก Android**
- [ ] เปิดวิดีโอที่ iPhone ส่งขึ้นมา **ด้วยเครื่อง Android** — ต้องเล่นได้
- [ ] ทดสอบเลือกหลายไฟล์พร้อมกัน 10 ไฟล์
- [ ] เปลี่ยนภาษาเป็น **BM** และ **EN** อ่านรู้เรื่องทั้งสองภาษา
- [ ] เขียนคำอวยพรพร้อมแนบรูปได้
- [ ] เช็คพื้นที่ว่าง `df -h /volume1` — ควรเหลือ **อย่างน้อย 50 GB**
- [ ] `BASE_URL` ใน `.env` ตรงกับที่อยู่จริง
- [ ] **สั่งพิมพ์การ์ด QR** แล้วสแกนใบที่พิมพ์จริงหนึ่งครั้ง
- [ ] NAS ไม่ได้ตั้ง auto-shutdown / hibernate ในช่วงวันงาน
  (Control Panel → Hardware & Power → Power Schedule)

## 🗓 1 วันก่อนงาน

- [ ] ลบรูปทดสอบทั้งหมดออกจาก `/admin`
- [ ] ตั้ง `UPLOAD_WINDOW` (ถ้าใช้) หรือเปิดสวิตช์อัพโหลดไว้
- [ ] `sudo docker compose ps` — สถานะต้องเป็น `Up (healthy)`
- [ ] ล็อกอิน `/admin` ค้างไว้ในมือถือเจ้าภาพ **และ** มือถือคนช่วยอีก 1 คน
- [ ] ชาร์จโน้ตบุ๊กเครื่องฉายจอ + เตรียมสาย HDMI และตัวแปลง
- [ ] เตรียมการ์ด QR แยกใส่ซองตามโต๊ะเรียบร้อย
- [ ] จดที่อยู่เว็บและรหัส `/admin` ใส่กระดาษไว้ในกระเป๋า (เผื่อมือถือแบตหมด)
- [ ] แจ้งพิธีกรให้ประกาศชวนแขกสแกน QR ช่วงต้นงาน

## 🎉 วันงาน — ก่อนแขกมา 30 นาที

- [ ] เปิดเว็บจากมือถือ 1 เครื่อง เช็คว่ายังขึ้นปกติ
- [ ] เปิดหน้า `/slideshow` เต็มจอบนโปรเจกเตอร์/ทีวี
- [ ] อัพโหลดรูปทดสอบ 1 ใบ → ขึ้นจอภายใน 30 วินาที → แล้วลบทิ้ง
- [ ] วางการ์ด QR ครบทุกโต๊ะ + จุดลงทะเบียน
- [ ] เช็ค Wi-Fi ของสถานที่ (ถ้ามี) และแจ้งรหัสให้แขก

## 🎉 ระหว่างงาน

- [ ] ดูจอสไลด์โชว์เป็นระยะ — มีรูปไม่เหมาะให้กด **ลบ** ที่ `/admin`
- [ ] ช่วงกลางงาน ลองเช็คว่ามีรูปเข้ามาจริง (`/admin` → ตัวเลขสถิติ)
- [ ] ถ้าไม่มีใครส่งรูปเลย → ให้พิธีกรประกาศซ้ำ หรือเดินชวนโต๊ะแรก ๆ
- [ ] แขกบางคนอาจถามว่า "ต้องโหลดแอปไหม" → **ไม่ต้อง สแกนแล้วใช้ได้เลย**

## 🌙 หลังงานจบ

- [ ] ปิดสวิตช์ **เปิดให้แขกอัพโหลด** ที่ `/admin`
- [ ] ดาวน์โหลด ZIP ทั้งหมด ([บทที่ 5](05-download-backup.md))
- [ ] สร้าง PDF **สมุดคำอวยพร** และ **รายชื่อผู้ส่งภาพ** ที่ `/admin` แล้วดาวน์โหลดเก็บไว้
- [ ] สำรองข้อมูลลงที่อื่นอย่างน้อย 1 ที่ ภายใน 24 ชั่วโมง
- [ ] แชร์ลิงก์ให้แขกเข้ามาดูรูปย้อนหลังได้อีกสัก 1–2 เดือน

## 🚨 แก้ปัญหาเฉพาะหน้า

| อาการ | ทำอะไร |
|---|---|
| แขกอัพโหลดไม่ได้ทุกคน | เช็คว่าคอนเทนเนอร์ยังรัน: `sudo docker compose ps` → ถ้าไม่ขึ้น `Up` ให้ `sudo docker compose up -d` |
| อัพวิดีโอไม่ผ่าน แต่รูปได้ | ลิมิต nginx หาย — ทำ[ข้อ 5 ของบทที่ 2](02-ddns-reverse-proxy.md#5--แก้ลิมิตขนาดอัพโหลดของ-nginx-ห้ามข้าม) ซ้ำแล้วรีสตาร์ท nginx |
| เว็บเข้าไม่ได้จากข้างนอก แต่ใน Wi-Fi บ้านได้ | เกือบทุกครั้งคือ **ไอพีบ้านเปลี่ยน แต่ระเบียน DNS สาธารณะยังค้างที่เลขเก่า** → `sudo ./scripts/diagnose-nas.sh` ดูข้อ 9 แล้วแก้ด้วย `sudo ./scripts/cloudflare-ddns.sh` ([รายละเอียด](07-shafiq-nas.md#เข้าในบ้านได้-แต่จาก-4g5g-เข้าไม่ได้--ระเบียน-cloudflare-ค้างที่ไอพีเก่า)) |
| เปิดเว็บแล้วได้หน้า **Synology "page not found"** | ไม่ใช่แอปพัง — nginx ตอบเอง · เช็คก่อนว่าพิมพ์ `https://` นำหน้าหรือเปล่า แล้วรัน `sudo ./scripts/diagnose-nas.sh` ดูข้อ 6.5 กับ 8 |
| จอสไลด์โชว์ค้าง | กด F5 หนึ่งครั้ง — รูปทั้งหมดยังอยู่ครบ |
| รูปขึ้นช้ามาก | เน็ตในงานแน่น → เปลี่ยนเครื่องฉายจอให้ชี้ไป IP ใน LAN ตรง ๆ |
| ดิสก์ใกล้เต็ม | `/admin` → ลบวิดีโอที่ยาวผิดปกติออกก่อน หรือลด `MAX_VIDEO_MB` · **กดลบแล้วดิสก์ยังไม่ว่าง** เป็นเรื่องปกติ — รูปที่ลบเข้าถังขยะก่อน ไฟล์จริงยังอยู่จนกว่าจะครบ 7 วัน (ระบบกวาดทิ้งเองอย่างมากทุกชั่วโมง) เร่งด่วนจริง ๆ ตั้ง `TRASH_RETENTION_DAYS=0` ใน `.env` แล้ว `sudo docker compose up -d` รอไม่เกิน 1 ชั่วโมงให้กวาดรอบถัดไปทำงาน |
| ลืมรหัส `/admin` | แก้ `ADMIN_PASSWORD` ใน `.env` → `sudo docker compose up -d` (เซสชันเดิมยังใช้ได้จนหมดอายุ) |

**เบอร์ฉุกเฉินของตัวเอง**: จดชื่อคนที่ดูแลเรื่องนี้ไว้ให้พิธีกรและเจ้าภาพรู้
เผื่อระหว่างงานมีอะไรผิดพลาดจะได้เรียกถูกคน
