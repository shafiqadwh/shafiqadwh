## 0. เลือกก่อนว่ากำลังสร้างเครื่องแบบไหน — สามแบบ ไม่เหมือนกันเลย

อ่านข้อนี้ให้จบก่อนลงมือ เพราะการเลือกผิดแบบแปลว่าต้องลงใหม่ทั้งเครื่อง

| แบบ | เครื่องรันอะไร | ต้องมีเน็ตที่งานไหม | ใช้ตอนไหน |
|---|---|---|---|
| **ก. เว็บบน NAS ที่บ้าน** | เว็บอย่างเดียว (Docker) | ต้องมี — แขกเข้าจากมือถือตัวเอง | ลูกค้าเช่าเว็บแชร์รูป (โมเดล A) |
| **ข. บูธอย่างเดียว** | บูธอย่างเดียว | ไม่ต้อง ถ้าพิมพ์เท่านั้น | ลูกค้าเช่าบูธ พิมพ์แผ่นกลับบ้าน |
| **ค. กล่องเดียวจบ** | **เว็บ + บูธบนเครื่องเดียวกัน** | ไม่ต้อง | บูธ + สไลด์โชว์ขึ้นทีวี ในงานที่ไม่มีเน็ต |

**แบบ ค. คือคำตอบของงานรับปริญญา/งานรับรองที่ไม่มีอินเทอร์เน็ต** — เว็บไม่จำเป็นต้อง
อยู่บน NAS ที่บ้าน มันรันบนมินิพีซีตัวเดียวกับบูธได้ แล้วทีวีในงานเปิดสไลด์โชว์จาก
เครื่องนั้นผ่าน LAN ของเราเอง · แผ่นที่บูธถ่ายขึ้นจอทีวีให้เองอยู่แล้ว
(`withBoothSheets` ใน `src/routes/slideshow.js` มีสวิตช์ `slideshow_booth` เปิดไว้)

บทนี้เขียนเป็นทางของ **แบบ ค.** เพราะครอบมากที่สุด · ทำแบบ ข. ก็ข้ามหัวข้อ 5 กับ 10 ไป

## 1. ลง Ubuntu LTS รุ่น Desktop

เลือก **Desktop ไม่ใช่ Server** — Electron ต้องมีหน้าจอกราฟิกจริงถึงจะเปิดหน้าต่างได้
และเลือก **LTS** เพราะไม่มีอัปเดตบังคับรีสตาร์ตกลางงานที่แขกต่อแถวอยู่

### ทำแฟลชไดรฟ์

โหลด ISO รุ่น LTS ล่าสุดจาก `releases.ubuntu.com` แล้วเขียนลง USB ด้วย **Rufus** (Windows)
หรือ **balenaEtcher** · ขนาด USB 4 GB พอ

### ตอนลง

เสียบ USB เปิดเครื่อง กด `F2`/`F12`/`Del` เข้า BIOS (แล้วแต่ยี่ห้อ) เลือกบูตจาก USB

| ช่อง | เลือกอะไร | เพราะอะไร |
|---|---|---|
| ภาษา | English | ข้อความผิดพลาดของ Linux ค้นหาเจอง่ายกว่า ตั้งคีย์บอร์ดไทยทีหลังได้ |
| Installation type | **Interactive** / Normal | ต้องได้ของที่ติดมากับเดสก์ท็อปครบ |
| **Install third-party software** | ✅ ติ๊ก | ไดรเวอร์ Wi-Fi/กราฟิกบางตัวอยู่ในนี้ |
| Disk | Erase disk and install | เครื่องนี้มีงานเดียว ไม่ต้องแบ่งกับระบบอื่น |
| **Log in automatically** | ✅ **ติ๊ก** | **สำคัญ** — บูธต้องขึ้นเองหลังไฟดับ ถ้าต้องพิมพ์รหัสก่อน เครื่องจะค้างอยู่หน้าล็อกอินทั้งงาน |

เสร็จแล้วถอด USB รีสตาร์ต

### ปิดของที่รีสตาร์ตเองกลางงาน

```sh
sudo systemctl disable --now unattended-upgrades
```

อัปเดตเองตอนอยู่บ้าน ไม่ใช่ปล่อยให้เครื่องตัดสินใจเองตอนอยู่หน้างาน

### ปิดจอดับ/พักเครื่อง

เข้า **Settings → Power** แล้วตั้ง *Screen Blank* เป็น **Never** และปิด *Automatic Suspend*

> ตัวโปรแกรมกันจอดับให้อยู่แล้วระหว่างรอบถ่าย (`powerSaveBlocker` ใน
> `photobooth/src/main/main.js`) แต่ช่วงที่บูธยืนรออยู่เฉย ๆ เป็นหน้าที่ของระบบ

### Node.js 22

Ubuntu บางรุ่นมี Node ใน apt ที่ใหม่พอแล้ว บางรุ่นเก่าเกินไป · **ตรวจก่อนเสมอ

## 3. เอาโค้ดลงเครื่อง

**`git` ไม่ได้ติดมากับ Ubuntu** ต้องลงก่อน ไม่งั้นได้ `Command 'git' not found`
แล้วบรรทัดถัดไปจะล้มตาม ๆ กันเพราะโฟลเดอร์ยังไม่ถูกสร้าง

```sh
sudo apt update
```
```sh
sudo apt install -y git
```
```sh
git clone https://github.com/shafiqadwh/shafiqadwh.git ~/wedding
```
```sh
cd ~/wedding
```

repo เป็นแบบ public และ default branch คือสาขาที่ใช้งานอยู่ โคลนมาแล้วได้โค้ดล่าสุด
ทันทีโดยไม่ต้องใส่รหัสอะไร · `.env` ที่สคริปต์สร้างให้อยู่ใน `.gitignore` แล้ว
**กุญแจกับรหัสแอดมินจึงไม่มีทางหลุดขึ้น repo สาธารณะ** ต่อให้เผลอ `git add .`

ลง dependencies ของทั้งสองโปรแกรม — **ต้องอยู่ในโฟลเดอร์เดียวกัน** เพราะบูธ
เรียกใช้ `shared/` กับ `assets/` จากโฟลเดอร์แม่

```sh
npm ci
```
```sh
cd photobooth && npm ci && cd ..
```

### ตัวโปรแกรม Electron — ขั้นที่ลืมกันบ่อยที่สุด

```sh
cd photobooth && npm run install:electron && cd ..
```

**`npm ci` ไม่โหลดตัวโปรแกรม Electron ให้** ตั้งแต่ Electron 44 มันเลิกมี postinstall
ไบนารีราว 150 MB ถูกโหลดตอน `npm start` ครั้งแรกแทน — ซึ่งแปลว่า**ถ้าไม่สั่งตอนนี้
มันจะไปโหลดตอนเปิดบูธครั้งแรกที่หน้างาน ที่ไม่มีเน็ต** สั่งให้จบตอนยังอยู่บ้าน

ถ้า Electron เปิดไม่ขึ้นเพราะไลบรารีระบบขาด ใช้รายการของ playwright ซึ่งรู้ดีกว่าเราเดาเอง

```sh
npx playwright install-deps chromium
```

### สิทธิ์ของ chrome-sandbox — ไม่ตั้งแล้วบูธไม่เปิดเลย

`npm ci` ลงไฟล์ `chrome-sandbox` มาเป็นของผู้ใช้ธรรมดา แล้ว Electron **ปฏิเสธ
ที่จะเปิด** พร้อมข้อความว่า `The SUID sandbox helper binary was found, but is
not configured correctly` — ไม่ใช่คำเตือน แต่คือจบเลย

```sh
sudo chown root:root photobooth/node_modules/electron/dist/chrome-sandbox
```
```sh
sudo chmod 4755 photobooth/node_modules/electron/dist/chrome-sandbox
```

`install-ubuntu.sh` ทำให้เองแล้ว · **ต้องทำใหม่ทุกครั้งที่ `npm ci` ใหม่**
เพราะมันลบ `node_modules` ทิ้งแล้วลงใหม่ทั้งก้อน — รันสคริปต์ซ้ำก็จบ

อย่าแก้ด้วยการเติม `--no-sandbox` · sandbox คือชั้นที่กันหน้าเว็บไม่ให้แตะระบบ
การปิดเกราะทั้งเครื่องเพื่อประหยัดสองบรรทัดนี้ไม่คุ้มกัน

## 4. ตั้งค่า `.env` ของเว็บ

```sh
cp .env.example .env
```
```sh
nano .env
```

อย่างน้อยสามค่านี้

```dotenv
ADMIN_PASSWORD=รหัสของคุณอย่างน้อย8ตัว
BOOTH_KEY=สุ่มมาอย่างน้อย16ตัวเป็นอักษรอังกฤษตัวเลขสัญลักษณ์
BASE_URL=http://192.168.1.50:3000
```

**`BASE_URL` ต้องเป็นไอพีที่มือถือกับทีวีในงานเข้าถึงได้ ไม่ใช่ `localhost`** —
QR ที่พิมพ์ลงกระดาษแล้วแก้ทีหลังไม่ได้ ถ้าใส่ `localhost` แขกสแกนแล้วเปิดไม่ขึ้นทุกใบ

หาไอพีของเครื่องนี้

```sh
hostname -I
```

ตั้งไอพีนั้นให้นิ่งจาก **Settings → Network → IPv4 → Manual** ไม่ใช่ปล่อยให้ DHCP
แจกใหม่ทุกครั้งที่เปิดเครื่อง ไม่งั้นกระดาษที่พิมพ์เมื่อวานชี้ไปเครื่องที่ไม่มีอยู่

`BOOTH_KEY` ว่าง = ปิดการรับรูปจากบูธ ซึ่งเป็นค่าปลอดภัยที่ตั้งใจ · ต้องเป็นอักษร
ASCII ที่พิมพ์ได้ และยาวอย่างน้อย 16 ตัว

### ⚠ ตั้งชื่องานกับวันที่ให้เสร็จ **ก่อน** เปิดเซิร์ฟเวอร์ครั้งแรก

ครั้งแรกที่รัน `npm start` ระบบสร้างทะเบียนงานขึ้นมาแล้ว **จด `EVENT_TITLE` กับ
`EVENT_DATE` ลงไปในนั้น** จากนั้นทะเบียนจะชนะ `.env` ตลอดไป

ผลที่เกิดจริงถ้าแก้ทีหลัง: `EVENT_NAMES` เปลี่ยนตามไฟล์ แต่ชื่อบนแถบแท็บกับวันที่
บนหน้าเว็บ **ไม่เปลี่ยน** — บางช่องขยับบางช่องไม่ขยับ ซึ่งอ่านแล้วเหมือนแคชค้าง
ทั้งที่ไม่ใช่ (เจอจริงตอนตั้งเครื่องใหม่)

แก้ทีหลังได้ที่ **`/console`** ซึ่งเป็นที่ที่ควรแก้อยู่แล้วเมื่อเริ่มมีลูกค้าจริง
เพราะเปลี่ยนได้ทุกช่องและแยกต่อลูกค้า ไม่ต้องรีสตาร์ทเซิร์ฟเวอร์ด้วย

## 8. กล้อง DSLR ต่อสาย (Linux เท่านั้น)

`gphoto2` ไม่มีบน Windows — นี่คือเหตุผลข้อหลักที่บูธควรเป็น Linux

```sh
sudo apt install -y gphoto2
```

เสียบกล้อง **เปิดสวิตช์กล้อง** แล้วตรวจว่าเห็น

```sh
gphoto2 --auto-detect
```

### สามกับดักที่เจอจริง และโปรแกรมบอกทางแก้ให้เองแล้ว

| อาการ | ทางแก้ |
|---|---|
| `Could not claim the USB device` | เดสก์ท็อปของ Ubuntu ไปเมาต์กล้องเป็นไดรฟ์ก่อน — `pkill -f gvfs-gphoto2` แล้วลองใหม่ |
| โฟกัสไม่เข้า ลั่นชัตเตอร์ไม่ออก | **ตั้งเลนส์เป็น MF** บูธควรเป็น MF อยู่แล้วเพราะเร็วกว่าและไม่หลุดกลางคิว |
| `command not found` | ยังไม่ได้ลง gphoto2 |
| `PTP Store Not Available` | **ไม่มีการ์ดในกล้อง** · ตรวจด้วย `gphoto2 --storage-info` ว่างเปล่า = ไม่มีที่เก็บเลย · ใส่การ์ดแล้วฟอร์แมตในกล้องหนึ่งครั้ง · ถ้าใส่แล้วยังไม่ได้ ดูเมนู **Slot empty release lock** ต้องเป็น Enable release |

ข้อความผิดพลาดของ `gphoto2` ถูกแปลเป็นสิ่งที่คนหน้าบูธลงมือแก้ได้แล้วใน
`photobooth/src/main/camera.js` — ไม่ต้องจำตารางนี้ หน้าจอจะบอกเอง

ในหน้าตั้งค่าเลือกตัวถ่ายเป็น **dslr** แล้วกดปุ่มทดสอบถ่าย

> `gphoto2` คืนรหัส 0 ได้ทั้งที่ไฟล์ถูกตัดกลางคัน (สาย USB หลวม การ์ดเต็ม)
> โปรแกรมจึงตรวจไฟล์ที่ได้จริงด้วย ไม่เชื่อรหัสผลลัพธ์อย่างเดียว

### ชุด HDMI + capture card — ถ้าอยากให้พรีวิวตรงกับเลนส์

แบบที่แนะนำคือเว็บแคมทำพรีวิว กล้องใหญ่ตื่นเฉพาะตอนลั่นชัตเตอร์ กล้องจึงเย็นและ
แบตอยู่ทั้งคืน · แต่ถ้าต้องการให้ภาพบนจอเป็นเฟรมเดียวกับเลนส์เป๊ะ ต่อ HDMI ของกล้อง
เข้า capture card แล้วเสียบ USB เข้าเครื่อง การ์ดจะขึ้นเป็นเว็บแคมตัวหนึ่ง

#### มี capture card แล้ว ยังต้องต่อสาย USB เข้ากล้องอีกไหม — **ต้อง**

ชุดนี้ใช้ **สองสาย** ไม่ใช่สายเดียว และสองสายทำคนละหน้าที่กันคนละเรื่อง

| สาย | ไปไหน | ทำอะไร | ทดแทนกันได้ไหม |
|---|---|---|---|
| **HDMI** | กล้อง → capture card → USB ของเครื่อง | **ภาพสดขาออกทางเดียว** สำหรับโชว์บนจอ | ไม่ |
| **USB** | กล้อง → เครื่องโดยตรง | **สั่งงานกล้อง** (gphoto2) | ไม่ |

HDMI เป็นทางเดินภาพ **ทิศทางเดียว** — กล้องส่งออก เครื่องรับเข้า จบ · ไม่มีช่องทาง
ให้เครื่องส่งคำสั่งย้อนกลับไปเลย สิ่งที่หายไปถ้าไม่ต่อ USB:

1. **ลั่นชัตเตอร์ไม่ได้** เครื่องสั่งกล้องถ่ายไม่ได้ ต้องมีคนกดชัตเตอร์ที่ตัวกล้อง
   ซึ่งขัดกับบูธที่แขกกดเอง
2. **ไม่ได้ไฟล์เต็ม** ภาพจาก HDMI คือภาพพรีวิววิดีโอ ราว 1920×1080 = 2 ล้านพิกเซล
   ส่วนไฟล์จริงจากเซนเซอร์ D7000 คือ 16 ล้านพิกเซล · ตัดจาก HDMI มาพิมพ์ 4×6
   ก็ได้แค่คุณภาพเท่าวิดีโอ ซึ่งแปลว่าซื้อกล้องใหญ่มาแล้วไม่ได้ใช้
3. **แก้ปัญหา Live View หลุดไม่ได้** คำสั่งที่พากล้องกลับเข้า Live View หลังถ่าย
   (`viewfinder=1`) เดินทางไปทาง USB เท่านั้น — ซึ่งก็คือปัญหาที่ชุดนี้ต้องแก้พอดี

ฉะนั้นในหน้าตั้งค่า ชุดนี้ต้องติ๊กสองอย่างพร้อมกัน: **"ถ่ายด้วยกล้อง DSLR"**
(ลั่นชัตเตอร์ผ่าน USB ได้ไฟล์เต็ม) และ **"ภาพสดมาจาก HDMI ของกล้อง"**
(พรีวิวมาจากการ์ด และพากล้องกลับเข้า Live View ให้เอง)

ติ๊ก **"ภาพสดมาจาก HDMI ของกล้อง"** ในหน้าตั้งค่า เพราะ **การลั่นชัตเตอร์พากล้อง
ออกจาก Live View ทุกครั้ง** ภาพสดจะหายหลังถ่ายรูปแรกแล้วรอบถัดไปหากล้องไม่เจอ
ติ๊กแล้วโปรแกรมสั่งกล้องกลับเข้า Live View ให้เองหลังถ่ายเสร็จ

สามอย่างที่ต้องยอมรับพร้อมกับชุดนี้ ไม่มีซอฟต์แวร์ตัวไหนแก้ให้ได้

| เรื่อง | ความจริง | ต้องทำอะไร |
|---|---|---|
| **ไฟ** | Live View ค้างกินแบตหมดในราวหนึ่งชั่วโมง | **ต้องมีอะแดปเตอร์ไฟบ้าน** (EH-5 + EP-5B สำหรับ D7000) ข้อนี้บังคับ ไม่ใช่ทางเลือก |
| **ความร้อน** | เซนเซอร์อ่านค่าตลอดเวลา กล้องจะปิด Live View เองเมื่อร้อนถึงจุดหนึ่ง | พัดลมเป่าช่วยได้ แต่ไม่ได้แก้หมด ดูข้างล่าง |
| **หน้าจอ** | HDMI ของ D7000 ไม่ใช่ clean output มีกรอบโฟกัสกับตัวเลขติดมาด้วย | ลองดูด้วยตาก่อนตัดสินใจซื้อการ์ด |

ตั้งในเมนูกล้องด้วย: **Custom Setting c4 → Monitor off delay → Live view** ตั้งให้
นานที่สุด ไม่งั้นกล้องปิด Live View เองตอนไม่มีคนถ่ายนาน ๆ

#### โปรแกรมจับการ์ดค้างไว้ ไม่ปล่อยระหว่างรอบ

เดิมโปรแกรมปิดกล้องทุกครั้งที่จบรอบ เพื่อไม่ให้ไฟเว็บแคมติดค้างหลังจอกลับไปหน้า
พร้อม · เหตุผลนั้นใช้ได้กับเว็บแคม แต่กับ capture card **การปล่อยอุปกรณ์คือการ
ตัดสัญญาณเข้า** แล้วรอบถัดไปต้องไปจับการ์ดใหม่ ซึ่งเป็นจังหวะที่ล้มบ่อยที่สุด

ตอนนี้สัญญาณถูกจับค้างไว้ตั้งแต่รอบแรกจนปิดหน้าบูธ · ราคาที่ยอมจ่ายคือ **ไฟกล้อง
ติดตลอดเวลาที่บูธเปิดอยู่** ซึ่งเทียบกับบูธที่ถ่ายรอบสองไม่ได้แล้วรับได้สบาย ๆ
ถ้าสายหลุดกลางทาง โปรแกรมขึ้นข้อความแล้วคืนจอให้ลองใหม่ และจับสัญญาณใหม่ให้เอง

**ข้อนี้ยังไม่ได้ยืนยันกับ D7000 และการ์ดตัวจริง** — ยังเป็นการแก้ฝั่งโปรแกรม
อย่างเดียว ถ้ากล้องยังหลุดออกจาก Live View อยู่ ให้ไล่ตามค่าในเมนูกล้องข้างบนก่อน

##### ตรวจรับหกข้อบนเครื่องจริง (ทำก่อนรับงานแรกที่ใช้ชุดนี้)

| # | ทำอะไร | ผ่านคือ |
|---|---|---|
| 1 | ตั้งจัดท่า 15 นับถอยหลัง 3 แล้วยืนเฉย ๆ | เริ่มถ่ายเองเมื่อครบ 18 วินาที |
| 2 | ถ่ายและพิมพ์สามรอบติดกัน | **ไม่ต้องเปิด Live View ใหม่เลยสักรอบ** |
| 3 | กดถ่ายใหม่จากหน้าดูแผ่น | กลับมาหน้าจัดท่าอีกครั้ง และ**ไม่เก็บเงินซ้ำ** |
| 4 | กด "กลับ" ระหว่างจัดท่า แล้วรอเกิน 15 วินาที | ไม่มีการถ่ายเอง |
| 5 | ถอดแล้วเสียบ USB ของการ์ดกลับ แล้วลองใหม่ | ขึ้นข้อความบอก และต่อสัญญาณใหม่ได้ |
| 6 | ปิดโปรแกรม | กล้องถูกคืนให้โปรแกรมอื่นใช้ได้ |

| `printPage = A4` | วาง 4×6 ลงบน A4 **ขนาดจริงไม่ถูกย่อ** สองใบต่อแผ่น พร้อมเส้นตัด — ประหยัดกระดาษกับหมึกเท่าตัว |

## 10. รีโมทกดถ่าย · จอที่สอง · ทีวี

### รีโมท

รีโมทกดถ่ายที่ขายกันคือ **คีย์บอร์ดตัวหนึ่ง** เสียบแล้วใช้ได้เลย ไม่ต้องลงอะไร
**ค่าเริ่มต้นคือไม่จดปุ่มอะไรเลย** โดยตั้งใจ เพราะการยึด `Enter` ไว้ทั้งเครื่องแปลว่า
โปรแกรมอื่นใช้ปุ่มนั้นไม่ได้ · เข้าหน้าตั้งค่าแล้วเลือกปุ่มที่ต้องการเอง
ปุ่มที่ระบบอื่นยึดไว้อยู่จะไม่ถูกแย่งเงียบ ๆ — หน้าจอจะบอกว่าจดไม่ได้

### จอที่สอง (จอช่างภาพ)

เสียบสาย HDMI เส้นที่สอง · โปรแกรมแจกหน้าต่างให้เองคือ **จอหลักเป็นของแขก
จออีกตัวเป็นของช่างภาพ** · จอเดียวได้หน้าต่างเดียว ไม่ใช่สองใบซ้อนกัน
และจอที่ตั้งเป็น mirror กันนับเป็นจอเดียว

### ทีวีในงาน

ทีวีเปิดหน้าสไลด์โชว์ของเว็บ มีสองทาง

1. **Google TV APK** ที่มีอยู่แล้ว — เปิดแล้วกรอกรหัสจับคู่ 6 หลักที่ขึ้นบนจอทีวี
   ลงในหน้าแอดมิน ดูบทที่ 4 · รหัสจับคู่อยู่ในทะเบียนกลาง ไม่ใช่ในฐานข้อมูลของงาน
   ทีวีเครื่องเดียวจึงยกไปใช้ได้ทุกงานโดยไม่ต้องตั้งใหม่
2. **เบราว์เซอร์บนทีวี** เปิด `http://<ไอพีเครื่อง>:3000/slideshow?mode=wall`

โหมดจอผูกกับ **ทีวีแต่ละเครื่อง** ไม่ใช่กับงาน สองงานในวันเดียวจึงใช้ทีวีเครื่องเดิมได้

## 11. ให้ทุกอย่างขึ้นเองหลังไฟดับ

นี่คือข้อที่ทำให้ "ปล่อยบูธทำงานเองโดยไม่มีเราอยู่" เป็นไปได้จริง

> ⚠️ **ยังไม่มีสคริปต์ตั้งให้อัตโนมัติบน Linux** — มีแต่ของ Windows
> (`photobooth/scripts/windows-setup.ps1`) คำสั่งข้างล่างนี้คือสิ่งที่สคริปต์นั้นทำ
> แปลมาเป็น Linux · **ผมยังไม่ได้รันบนเครื่องจริง** ดูหัวข้อ 13

### เว็บ — systemd

```sh
sudo nano /etc/systemd/system/wedding-web.service
```

```ini
[Unit]
Description=Wedding photo share
After=network-online.target

[Service]
Type=simple
User=ชื่อผู้ใช้ของคุณ
WorkingDirectory=/home/ชื่อผู้ใช้ของคุณ/wedding
ExecStart=/usr/bin/npm start
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```sh
sudo systemctl enable --now wedding-web
```
```sh
systemctl status wedding-web
```

### บูธ — autostart ของเดสก์ท็อป ไม่ใช่ systemd

บูธต้องเปิดหน้าต่างบนหน้าจอของผู้ใช้ที่ล็อกอินอยู่ systemd แบบ system service
จึงไม่เหมาะ · ใช้ autostart ของเดสก์ท็อปคู่กับตัวเปิดที่เปิดใหม่เองเมื่อปิดไป

```sh
mkdir -p ~/.config/autostart ~/wedding/photobooth/scripts
```
```sh
nano ~/wedding/photobooth/scripts/booth-start.sh
```

```sh
#!/bin/sh
# ตัวเปิดบูธ — เปิดใหม่เองเมื่อปิดไป แต่ไม่เกิน 10 ครั้งติดกัน
#
# **มีเพดานโดยตั้งใจ** — ปิดเพราะตั้งค่าผิดจะปิดทันทีทุกครั้ง วนไม่จำกัดคือเครื่อง
# ที่หมุนอยู่อย่างนั้นทั้งคืนโดยไม่มีอะไรบนจอบอกว่าเกิดอะไรขึ้น
cd "$(dirname "$0")/.." || exit 1
tries=0
while [ "$tries" -lt 10 ]; do
  npm start
  tries=$((tries + 1))
  sleep 3
done
echo "บูธปิดตัวเอง 10 ครั้งติดกัน — หยุดลองใหม่แล้ว ดูข้อความข้างบนเพื่อหาสาเหตุ"
```

```sh
chmod +x ~/wedding/photobooth/scripts/booth-start.sh
```
```sh
nano ~/.config/autostart/photobooth.desktop
```

```ini
[Desktop Entry]
Type=Application
Name=Photo Booth
Exec=/home/ชื่อผู้ใช้ของคุณ/wedding/photobooth/scripts/booth-start.sh
X-GNOME-Autostart-enabled=true
```

### ซ้อมของจริงหนึ่งครั้ง — ข้อนี้สำคัญกว่าทุกข้อข้างบนรวมกัน

**ดึงปลั๊กเครื่อง** แล้วเสียบกลับ จับเวลา

- เครื่องต้องล็อกอินเข้าเดสก์ท็อปเอง (ข้อนี้คือเหตุผลที่ติ๊ก auto login ในหัวข้อ 1)
- บูธต้องขึ้นเอง
- เว็บต้องตอบเอง
- ทีวีต้องกลับมาเล่นสไลด์โชว์เอง

ซ้อมจริงหนึ่งครั้งที่บ้าน ดีกว่าค้นพบที่หน้างานว่าข้อไหนไม่ทำงาน

| กำลังถ่าย | นับถอยหลังแล้วเก็บภาพ | ถ่ายครบตามแบบแผ่น |
| ดูแผ่น / ส่งมอบ | แผ่นที่ได้ ปุ่มพิมพ์หรือถ่ายใหม่ | — |

**ขั้นจัดท่าเป็นขั้นที่เพิ่มมาทีหลังเพราะของจริงบอกว่าต้องมี** เดิมกดปุ่มเดียวแล้ว
นับถอยหลังสามวินาทีเลย ซึ่งพอสำหรับคนเดียว แต่กลุ่มที่มากันห้าคนจัดแถวไม่ทัน
ได้รูปที่ครึ่งกลุ่มยังไม่เข้าเฟรม และเป็นรูปที่ลูกค้าจ่ายเงินไปแล้ว

ขั้นนี้ให้เวลาจัดแถวเต็มที่ แขกเห็นตัวเองเต็มจอ ขยับจนพอใจ แล้วกดเองเมื่อพร้อม

**นาฬิกาบนขั้นนี้เป็นเพดาน ไม่ใช่การบังคับรอ** — กดเองได้ตลอดเวลาเพื่อไม่ต้อง
รอจนครบ แต่ถ้าไม่มีใครกด พอหมดเวลาโปรแกรมจะถ่ายให้เองจนครบทุกรูป เหตุผลคือ
บูธจริงเป็นจอสัมผัสล้วน **ไม่มีเมาส์ไม่มีคีย์บอร์ด** และแขกที่ยืนอยู่หน้ากล้อง
มักไม่กล้าแตะจอเองเพราะกลัวกดผิด · ถ้าไม่มีอะไรเดินหน้าให้ บูธจะค้างอยู่ตรงนั้น
จนกว่าจะมีคนเดินมาช่วย ซึ่งเท่ากับไม่มีบูธ

ตั้งเวลาได้ที่หน้าตั้งค่า ช่อง **"เวลาจัดท่าก่อนถ่ายเอง"** (`frameSeconds` ·
**ค่าเริ่มต้น 15 วินาที** รับได้ 10–120) · ต่ำกว่า 10 คือจัดแถวไม่ทันซึ่งเป็น
ปัญหาที่ขั้นนี้มีไว้แก้ เกินสองนาทีคือจอที่ค้างอยู่กับคนที่เดินไปแล้ว

> **เครื่องที่เคยตั้ง 30 ไว้จะยังเป็น 30** ค่าเริ่มต้นใช้กับเครื่องที่ยังไม่เคย
> บันทึกค่าเท่านั้น · อยากได้ 15 ให้เข้าหน้าตั้งค่าแล้วแก้เอง

เวลารวมจากกดเริ่มถึงชัตเตอร์แรก = เวลาจัดท่า + เวลานับถอยหลัง (15 + 3 = 18 วินาที
ด้วยค่าเริ่มต้น) · สองค่านี้คนละตัวและทำคนละหน้าที่ — ตัวแรกให้เวลาจัดแถว ตัวหลัง
บอกจังหวะว่าชัตเตอร์จะลั่นเมื่อไร

ปุ่ม **"กลับ"** บนขั้นนี้ยกเลิกการจัดท่าแล้วคืนจอให้คนถัดไป · **ตั๋วที่จ่ายเงิน
มาแล้วไม่หายไปกับการกดกลับ** คนเดิมกดเริ่มใหม่ได้โดยไม่ต้องจ่ายซ้ำ

ตัวจับเวลา "ไม่มีคนอยู่" (`BOOTH_IDLE_MS`) **ไม่แตะขั้นนี้เลย** — คนกำลังยืน
จัดแถวอยู่หน้ากล้อง จอต้องไม่รีเซ็ตทิ้งกลางคัน · ตั๋วที่จ่ายเงินมาแล้วก็ไม่หายไป
กับการหมดเวลาในขั้นไหนทั้งนั้น

## 12.5 อัปเดตเป็นเวอร์ชันใหม่ทับของเดิม

**ห้ามลบโฟลเดอร์เก่าแล้วลงใหม่** — ทำแบบนั้นรูปของงานที่ผ่านมา สมุดบัญชีการขาย
และค่าตั้งทั้งหมดหายไปพร้อมกัน · การอัปเดตที่ถูกต้องคือ **เขียนทับเฉพาะโค้ด**

### ของอะไรรอด ของอะไรถูกเขียนทับ

| ของ | อยู่ที่ไหน | ตอนอัปเดต |
|---|---|---|
| ค่าตั้งบูธ (ชื่องาน ราคา เครื่องพิมพ์) | `~/.config/photobooth/booth/settings.json` | **ไม่ถูกแตะ** — อยู่นอกโฟลเดอร์โค้ด |
| รูปทุกรอบที่ถ่ายไว้ | `~/.config/photobooth/booth/sessions/` | **ไม่ถูกแตะ** |
| สมุดบัญชีการขาย | `~/.config/photobooth/booth/sales/` | **ไม่ถูกแตะ** |
| ฐานข้อมูลเว็บกับรูปของแขก | `~/wedding/data/` | **ไม่ถูกแตะ** (อยู่ใน `.gitignore`) |
| กุญแจกับค่าตั้งเว็บ | `~/wedding/.env` | **ไม่ถูกแตะ** (อยู่ใน `.gitignore`) |
| โค้ดโปรแกรมทั้งหมด | `~/wedding/src`, `~/wedding/photobooth` | **ถูกเขียนทับ** — คือสิ่งที่ตั้งใจอัปเดต |

### ขั้นตอน

**1 · ปิดโปรแกรมที่รันอยู่ก่อน** อัปเดตทับโปรแกรมที่กำลังทำงานคือขอปัญหา

```sh
pkill -f electron
pkill -f 'node src/server.js'
```

**2 · สำรองไว้ก่อน** ใช้เวลาสิบวินาที และเป็นสิบวินาทีที่คุ้มที่สุดในคู่มือนี้

```sh
cp -a ~/.config/photobooth/booth ~/booth-backup-$(date +%F)
cd ~/wedding && tar czf ~/wedding-data-$(date +%F).tgz data .env
```

**3 · จดเลขเวอร์ชันปัจจุบันไว้** เผื่อต้องย้อนกลับ

```sh
cd ~/wedding && git rev-parse --short HEAD
```

จดเลขเจ็ดหลักที่ขึ้นมาไว้ในกระดาษหรือแชต

**4 · ตรวจว่าไม่ได้แก้ไฟล์โค้ดค้างไว้บนเครื่องนี้**

```sh
cd ~/wedding && git status --short
```

ไม่มีอะไรขึ้นมาเลย = พร้อมดึงของใหม่ · ถ้ามีบรรทัดขึ้นต้นด้วย `M` แปลว่ามีคนแก้
ไฟล์นั้นบนเครื่องนี้ แล้ว `git pull` จะไม่ยอมทับ — ทิ้งของที่แก้ไว้ด้วย
`git checkout -- <ชื่อไฟล์>` หรือเก็บไว้ก่อนด้วย `git stash`

**5 · ดึงโค้ดใหม่**

```sh
cd ~/wedding && git pull origin claude/wedding-photo-sharing-qr-j1oxn8
```

**6 · ลงของที่เพิ่มมาใหม่ ด้วยสคริปต์ตัวเดิม**

```sh
cd ~/wedding && ./scripts/install-ubuntu.sh --camera --printer
```

**รันซ้ำได้ปลอดภัยและต้องรันทุกครั้งที่อัปเดต** ไม่ใช่เฉพาะครั้งแรก เพราะสคริปต์นี้
ทำสามอย่างที่ `git pull` ทำให้ไม่ได้:

- ลง dependency ที่เพิ่มมาใหม่ (`npm ci` — ข้ามเองถ้า lockfile ไม่ได้เปลี่ยน)
- โหลดตัวโปรแกรม Electron ถ้าเวอร์ชันขยับ
- **ตั้งสิทธิ์ `chrome-sandbox` ใหม่** ข้อนี้สำคัญที่สุด · `npm ci` ลบ `node_modules`
  ทิ้งทั้งก้อนแล้วลงใหม่ สิทธิ์ setuid จึงหายไปด้วยทุกครั้ง และ **บูธจะไม่เปิดเลย**
  ถ้าไม่ตั้งใหม่ (เจอจริงมาแล้วบนเครื่องนี้)

⚠️ **ห้ามใส่ `sudo` หน้าสคริปต์** — ไฟล์จะกลายเป็นของ root แล้วเปิดโปรแกรมด้วย
ผู้ใช้ปกติไม่ได้ · สคริปต์ขอ sudo เองเฉพาะบรรทัดที่ต้องใช้

**7 · ตรวจว่าเวอร์ชันใหม่ทำงานจริงก่อนเอาออกงาน**

```sh
cd ~/wedding && npm test
```

ต้องผ่านหมดและ **`# skipped 0`** · มี skip เยอะแปลว่าไบนารี Electron ยังลงไม่ครบ

**8 · เปิดใช้งาน**

```sh
cd ~/wedding/photobooth && npm start
```

### ถ้าเวอร์ชันใหม่มีปัญหา — ย้อนกลับ

ใช้เลขเจ็ดหลักที่จดไว้ในขั้นที่ 3

```sh
cd ~/wedding
git checkout <เลขที่จดไว้>
./scripts/install-ubuntu.sh --camera --printer
```

กลับมาเวอร์ชันล่าสุดอีกครั้งเมื่อไรก็ได้ด้วย

```sh
cd ~/wedding && git checkout claude/wedding-photo-sharing-qr-j1oxn8
```

**ค่าตั้งกับรูปไม่หายไปกับการย้อนกลับ** เพราะอยู่คนละที่กับโค้ดตั้งแต่ต้น

### ปัญหาที่เจอบ่อยตอนอัปเดต

| อาการ | สาเหตุ | แก้ยังไง |
|---|---|---|
| `Your local changes would be overwritten` | มีคนแก้ไฟล์โค้ดบนเครื่องนี้ | `git checkout -- <ไฟล์>` แล้ว pull ใหม่ |
| `Permission denied` ตอนรันสคริปต์ | บิตรันหาย | `chmod +x scripts/*.sh` |
| บูธขึ้น `chrome-sandbox ... mode 4755` แล้วปิดตัวเอง | ลืมรันสคริปต์ในขั้นที่ 6 | รันสคริปต์ให้ครบ |
| `EADDRINUSE` พอร์ต 3000 | เว็บตัวเก่ายังรันอยู่ | `pkill -f 'node src/server.js'` แล้วเปิดใหม่ |
| `npm ci` ค้างนานมาก | กำลังโหลด Electron ~150 MB | ปล่อยให้เสร็จ · **ต้องมีเน็ตตอนอัปเดต ห้ามอัปเดตหน้างาน** |

**กติกาข้อเดียวที่สำคัญที่สุด: อัปเดตที่บ้าน ไม่ใช่ที่หน้างาน** · อัปเดตแล้วถ่าย
ทดสอบหนึ่งรอบจนได้กระดาษออกมาจริง ค่อยยกเครื่องขึ้นรถ

## 13. สิ่งที่ยังไม่ได้ทดสอบบนเครื่องจริง — อ่านก่อนเชื่อบทนี้ทั้งบท

เขียนจากการอ่านโค้ดกับเอกสารของเครื่องมือแต่ละตัว **ไม่ใช่จากการลงเครื่องจริงตามนี้**
ข้อที่ยังไม่เคยผ่านมือจริง

- ขั้นตอนลง Ubuntu ทั้งหัวข้อ 1
- `wedding-web.service` กับ `booth-start.sh` ในหัวข้อ 11 — **ยังไม่เคยรัน**
- `scripts/install-ubuntu.sh` — **ตรรกะการตัดสินใจมีเทสต์คุมครบ 11 ข้อ**
  (`test/install-ubuntu.test.js` รันสคริปต์ตัวจริงกับ apt/npm/node ปลอม) แต่
  **ยังไม่เคยรันบนเครื่อง Ubuntu จริง** สิ่งที่เทสต์ตอบแทนไม่ได้คือ apt ลงของได้จริงไหม
  NodeSource ตอบอะไรกลับมา และ Electron โหลดครบไหม
- กล้อง DSLR จริง (D7000 ยังไม่ได้เสียบทดสอบ)
- เครื่องพิมพ์จริง ทั้งอิงค์เจ็ทและ dye-sub
- ชื่อขนาดกระดาษของ dye-sub รุ่นที่จะซื้อ

ที่**ผ่านของจริงแล้ว**คือตัวโปรแกรมทั้งสองฝั่ง เทสต์ 614 ข้อผ่านทั้งบนเครื่องพัฒนา
และบน GitHub Actions โดยไม่มีข้อใดถูกข้าม · เจอข้อไหนในบทนี้ไม่ตรงกับของจริง
แก้บทนี้ทันที อย่าปล่อยให้เอกสารกับเครื่องเล่าเรื่องคนละเรื่อง
